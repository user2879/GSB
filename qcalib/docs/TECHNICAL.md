# 技术说明：逐组量化标定与饱和截断组件

## 1. 设计目标与约束

- 仅依赖 Python 3.10+ 标准库；NumPy 只出现在确定性样本生成器中。
- 不使用容器、不访问网络、不依赖真实账号；所有产物写入本地可写目录。
- 任意编辑序列后的增量运行，与从空白全量重建**逐字段一致**。
- 单条非法输入不中止整体加载，统一沉淀为带业务码的 `Failure` 明细。

## 2. 分层架构

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 加载校验 | `config.py` | JSONL 特征表、逐组配置、列组映射的逐条校验 |
| 交换 | `exchange.py` | v1 定宽 / v2 JSON 解析、统一 IR、双向转换、旁路 |
| 标定 | `calibration.py` | 分位值、缩放因子、零点推导（纯函数） |
| 内核 | `kernel.py` | 定点重缩放、饱和截断、逐元素记录、累加越界 |
| 归因 | `attribution.py` | 容差判定、四来源误差分解、列组分层统计 |
| 缓存 | `store.py` / `fingerprint.py` | 内容寻址缓存、缓存键、精确失效 |
| 调度 | `pipeline.py` | 预算约束、线程池、稳定排序键、增量/全量统一 |
| 快照/编排 | `snapshot.py` / `runner.py` | 原子整体替换、版本识别、诊断报告 |

## 3. 确定性保证

1. 分位插值固定为线性插值，并列值取更低下标（`lower-index-on-equal`），
   规则写入每个标定产物的 `interpolation_rule` / `tie_break_rule`。
2. 定点中间量全部使用 Python `int`；浮点先经 `repr` 规范化再进入指纹，
   规避跨平台浮点哈希差异。
3. 所有 JSON 输出 `sort_keys=True`；任务、失效、复用清单均按
   `(group_id, column)` 稳定排序。
4. 指纹仅依赖内容（输入值指纹、参数指纹、位宽档位、交换版本号），
   不含时间戳、线程 id 或内存地址。

## 4. 定点与饱和语义

裁剪区间由 `qbits` 与 `fbits` 共同决定（`_clip_bounds`）：

- 对称：`[-(2^(qbits-fbits)-1), 2^(qbits-fbits)-1]`，零点恒为 0；
- 非对称：`[0, 2^(qbits-fbits)-1]`，零点由 `-q_lo/scale` 推导并裁剪。

尺度 = 分位幅值（对称）或分位跨度（非对称）除以有效整数档数，因此：

- 调大 `fbits` → 有效档数减少 → 尺度变大、整数变粗、更易饱和；
- 切换 `qbits` → 档数与零点允许区间同时变化。

饱和策略：

- `clip`：裁剪到区间端点，逐元素记录 `direction`（low/high）与 `raw_int`；
- `reject`：越界元素不参与累加，标记 `direction=reject`。

累加器为 Python 整数，按 `accumulator_bits`（默认 32）判越界，产出
`E_ACC_OVERFLOW` 并记录组、列、元素位置与当时累加值。

## 5. 误差归因

逐元素计算绝对/相对误差；真值为 0 时走 `absolute-zero` 分支，仅用绝对容差判定。
四个非负分量通过逐阶段理想重放得到：

- `quantile`：全范围理想尺度与分位标定尺度的重构差；
- `scale_quant`：分位尺度下整数网格（含零点）的舍入差；
- `saturation`：裁剪到可表示区间的重构差；
- `dequant_round`：反量化浮点表示残差（精确反量化时为 0）。

超差元素取最大分量为主导来源；列组层面汇总最大相对误差、截断比例、超差比例与
主导来源份额，并生成 `layer_conclusion`。

## 6. 缓存键与精确失效

- 缓存键：`cache_key(stage, upstream_fps, params_fp, qbits, fbits, exchange)`。
- 每条缓存记录引用其行集合 `row_refs` 与参数集合 `param_refs`。
- 运行器持久化“每列内容指纹 + 参数指纹 + 位宽档”作为输入状态；对比前后状态，
  仅对发生变化的列所在组调用 `invalidate_group`，下游三阶段键一并移除。
- 未命中的键才计算；命中键进入稳定有序的复用清单。

## 7. 调度与快照

- 任务按 `(group_id, column)` 排序，按顺序消耗单批元素预算；预算不足时剩余任务
  进入待办队列并逐条报 `E_CALIB_BUDGET_PENDING`。
- 线程池并发执行，但每个任务携带稳定排序键，回填前再次排序，因此并发结果与
  `max_workers=1` 的串行结果完全一致（测试 `test_parallel_equals_serial`）。
- 快照在目标目录旁的独立临时目录中写入，`os.replace` 原子替换；manifest 内容
  指纹与运行模式（增量/全量）无关，因此两种模式下相同输入产出相同指纹。

## 8. 验证结果（本机实测）

环境：Python 3.11.0rc1、NumPy 1.26.4，Linux，无网络。

- `python -m unittest discover -s tests`：**24 个用例全部通过**。
- 覆盖矩阵：
  - 加载校验：重复行、非法取值、未知组、缺列、空组、分位/位宽/小数位宽非法；
  - 交换：定宽往返、字段截断、非有限缩放、零点越界、升级/降级/旁路往返、残差；
  - 标定内核：分位端点/插值/并列、重复确定性、`fbits` 改变整数与饱和数、
    clip/reject、累加越界、零真值分支、四来源分量；
  - 管线：空跑全复用、单行修正仅失效所属组、增量==全量、预算待办稳定、
    并发==串行、快照版本识别、位宽切换与组划分调整的精确失效。
- `examples/run_demo.py` 实测：9 列全部完成标定，饱和元素 1–2 个/列，
  预算 72 时完成 2 列、7 列进入待办；单行修正后失效 9 键、复用 6 键，
  增量与空白全量分组负载逐字段相等。

## 9. 局限与扩展点

- 当前缓存以文件为载体，适合单进程；多进程共享时建议加文件锁或换成 SQLite。
- 误差归因的理想重放基于观测极值，适合本组件的表格张量；接入真实激活分布时可
  注入外部校准集替换理想尺度。
- `reject` 策略下越界元素不进入反量化，报告中以 `missing/reject` 分支单列。
