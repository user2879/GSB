# 设计说明：中文分词与词性标注增量交互组件

## 1. 总体结构

```
segpos_lab/
├── src/segpos/
│   ├── errors.py       # 业务错误码与失败清单条目
│   ├── fingerprint.py  # 规范化 JSON + SHA-256 确定性指纹
│   ├── models.py       # Config / ProbTable / Lexicon / Token 数据模型
│   ├── loader.py       # 句子、词典、概率表、配置、命令流加载校验
│   ├── segmenter.py    # 正向最大匹配（FMM）分词
│   ├── oov.py          # 连续单字片段的未登录词处理
│   ├── tagger.py       # 对数域维特比解码与定点量化置信度
│   ├── snapshot.py     # 事务式版本目录 + current 符号链接原子切换
│   ├── engine.py       # 精确失效、阶段缓存、预算调度、线程池
│   └── runner.py       # full / interactive / restore 三种 CLI 模式
├── scripts/            # 样本生成、等价性验证、预算演示
├── tests/              # 28 个 unittest 用例
└── samples/            # 固定种子样本与非法注入场景
```

## 2. 加载校验层

- 句子文件按 `ID<TAB>文本` 解析；空 ID、重复 ID、空文本、受控字符表外字符均产生
  `E_SENTENCE_INVALID`，合法句子继续处理。
- 词典每行 `词 词频 词性`；词形空、词频非正有限数、词性未在概率表声明均产生
  `E_LEXICON_INVALID`；同词形重复按词频累加，来源（文件:行号）全部保留在
  `LexiconEntry.sources`。
- 概率表的 start/transition/emission 矩阵逐格校验有限数值；非法格产生
  `E_PROB_TABLE_INVALID` 并跳过该格，其余格照常加载。
- 配置校验：并发数为 1..16 的整数；低置信度阈值在 [0,1]；定点位宽仅允许
  `(8,16,32)`，量化档位仅允许 `(256,1024,65536)`；平滑值为正概率 ε，
  维特比内部统一取 `log(ε)` 使用；OOV 规则仅允许 `equal|fixed_max`。
- 失败条目携带 `(code,key,reason,source,source_line)`，输出前按
  `(source_line,code,key)` 稳定排序，保证失败清单顺序与执行路径无关。

## 3. FMM 分词

- 每一步从当前位置取最长命中；同长度候选按 `(词频降序, 词形字典序)` 决断。
- 命中文本携带 `start/end` 字符位置、词形、依据词频与匹配长度；未命中切单字并标
  `source=single`。
- 内容指纹 = `SHA256("segment-content" | 文本指纹 | 命中词集合指纹)`，
  同句同词典快照下逐次运行逐词一致。

## 4. 未登录词处理

- 先把连续 `single` 片段按 `oov_max_length` 做硬分段（依据写入
  `segment_basis=hard_cap:N|...`），再在每个硬分段内按配置规则切分：
  - `equal`：按 `round(sqrt(n))` 计算块数，余数均摊到前置块（`equal:sqrt`）；
  - `fixed_max`：按最大词长顺序切块（`fixed_max:max_len`）。
- 两种规则在 n≥2 的片段上产生不同边界；OOV 词统一标 `source=oov`，
  与词典词 `source=lexicon` 明确区分。
- OOV 指纹由分词内容指纹、各单字片段指纹、规则参数指纹共同派生，
  规则切换会同时改变候选边界与指纹。

## 5. 维特比标注

- 标签按字典序编码；start/transition/emission 缺失格以 `log(ε)` 补齐，
  补齐的 `(词序号,词,标签)` 全部记录在 `smoothed_positions`。
- 前向递推与回溯完全按“词序号升序、词性编码升序”显式循环；并列分数使用严格
  大于替换，自然保留字典序最小标签。
- 边界置信度 = `exp(dp[t,k] - log-sum-exp(dp[t,:]))`；`log-sum-exp` 用显式
  有序循环实现，禁用 NumPy 默认数组归约。
- 整句归一化对数概率沿最优路径逐词有序累加，不使用默认数组归约顺序。
- 置信度先按量化档位落到桶，再按位宽量化为非负定点整数；阈值做同样量化后做
  整数比较，低于阈值进入低置信度清单。

## 6. 缓存键与精确失效

三个阶段的缓存键全部由原始输入派生（不依赖尚未生成的上游产物），因此任意时刻
可独立判定：

- segment：文本指纹 + 词典快照指纹
- oov：文本指纹 + 词典快照指纹 + OOV 参数指纹
- tag：文本指纹 + 词典快照指纹 + OOV 参数指纹 + 概率表指纹 + 标注参数指纹

失效规则：

- 增删词条 / 调整词频：仅命中引用该词条的句子失效（由分词阶段记录的
  `hit_entries` 反查）；
- 替换概率表：全部句子的 tag 阶段失效；
- 替换单句文本：仅该句失效；
- 未失效句子直接复用内存产物并累加 `reuse_counts`，不进入线程池。

## 7. 首响预算与并发

- 任务按阶段波次执行：segment → oov → tag，波内句子级线程池并行，波间严格顺序，
  避免下游在上游未完成时被调度。
- 每个任务携带稳定排序键 `句子ID::阶段名`，结果按该键归集，句子顺序、清单顺序
  与单线程按句子 ID 执行完全一致。
- 每条命令在 `first_response_budget_ms` 内返回最近完成状态；超时返回
  `E_INTERACT_BUDGET_PENDING`，未完成任务保留在待办列表，不计入已完成摘要，
  也不会写入“已完成”快照状态；后续命令或排空调用继续处理待办。
- `simulated_task_delay_ms` 是仅用于本地确定性测试的每任务延迟，默认 0。

## 8. 快照、恢复与报告

- 一次快照事务包含全部四个阶段：先在 `tmp/` 写完整候选目录，再原子
  `rename` 到 `versions/vN`，最后用 `os.replace` 原子切换 `current`
  相对符号链接。外部永远只能观察到完整快照。
- 清单记录全局版本、词典哈希、概率表哈希、预算消耗标记、待办句子、各阶段版本；
  提交按版本变化判定，未变化阶段不产生新版本。
- 强制终止只可能留下未链接的 tmp 残留；恢复仅信任 `current` 指向的完整版本，
  并输出恢复点版本号。
- 每次完整运行输出 JSON 诊断报告：总句数、成功/失败数、分词与 OOV 统计、
  低置信度清单、失效复用计数、快照版本、待办清单与各阶段耗时。

## 9. 增量与全量一致性

`scripts/verify_equivalence.py` 将同一命令流分别以块大小 1、2 与一次性提交驱动
增量引擎，并与“把全部命令应用到初始状态后再一次性全量运行”的结果逐字段比对：
分词/OOV/词性序列、来源标记、归一化对数概率、低置信度清单、失败清单完全一致。
