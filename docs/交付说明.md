# 本地确定性回执账本：交付说明

本目录交付一个可在 Windows 本地运行、也可在当前 Linux 工作区验证的 Python 3.11+ 包。所有推理均在本机 NumPy 与 `127.0.0.1` 回环子进程中完成，不依赖 Docker、外部账号或网络服务。

## 快速运行（Windows PowerShell）

```powershell
python --version
python -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File .\scripts\verify-windows.ps1
python -m receipt_ledger --ui
```

也可以分步执行：

```powershell
python -m receipt_ledger --generate-samples --sample-dir samples/local
python -m receipt_ledger --verify --sample-dir samples/local --runtime-dir .runtime
python -m pytest -q tests/test_receipt_ledger.py

python -m receipt_ledger --inject spec     --runtime-dir .runtime
python -m receipt_ledger --inject ref      --runtime-dir .runtime
python -m receipt_ledger --inject snapshot --runtime-dir .runtime
```

注入命令按设计返回退出码 `2`，并向 `.runtime/logs/injections.jsonl` 写入含 `monotonic_ms`、`code`、错误详情的结构化日志。

Tkinter 使用 CPython 官方 Windows 安装包自带的 tcl/tk；若安装时取消了 Tcl/Tk 组件，可重新运行安装器补齐。

## 代码地图

- `receipt_ledger/spec.py`：`workers.json`、`requests.json`、`rules.json` 加载、JSON Pointer 行号映射与 `E_SPEC` 强校验。
- `receipt_ledger/receipts.py`：r1/r2/r3 文本/JSON 回执编解码、字段补齐依据、`E_FIELD` 与 `E_REF`。
- `receipt_ledger/planner.py`：稳定批标识、确定性批计划与 `E_COVER` 覆盖/遗漏校验。
- `receipt_ledger/compute.py`：固定种子参数矩阵、整数定点 ReLU/线性前向、参数摘要与顺序无关输出摘要。
- `receipt_ledger/scheduler.py`：全局/每工作进程双上限、单调时钟等待时间、租约版本、续约、到期和配额回收的幂等权益释放。
- `receipt_ledger/worker.py`、`receipt_ledger/processes.py`：`127.0.0.1` JSON-line TCP 工作进程、客户端、子进程启动/强杀/重启。
- `receipt_ledger/invalidation.py`：`工作进程参数 -> 批次 -> 请求归属` 失效传播与最小重算集合。
- `receipt_ledger/ledger.py`：SQLite 原子批次事务、整数账本版本、内容摘要、快照导出/整体替换恢复。
- `receipt_ledger/replay.py`：恢复后用冻结请求和工作进程快照重算，并定位首个 `E_REPLAY` 批次与字段。
- `receipt_ledger/ui.py`：Tkinter 诊断台；数据库以 `mode=ro` 只读打开，刷新不写账本。
- `receipt_ledger/verification.py`：一键本地验收，包含真实回环子进程、强杀、恢复、快照替换和三类注入。
- `tests/test_receipt_ledger.py`：16 个聚焦测试。
- `samples/local/`：固定种子生成的声明、请求流、归并规则、三格式回执和批次对照清单。

## 稳定约定

### 批标识

批标识只由以下显式材料推导，不包含字典遍历顺序、派发顺序或可变参数版本：

```json
{"worker_id":"w-alpha","batch_index":0,"arrival_seqs":[0,3]}
```

序列化规则为 UTF-8、`sort_keys=True`、分隔符 `(",",":")`、不转义非 ASCII；批 ID 为 `rb1_` + SHA-256 前 20 位。任意请求派发顺序、worker 声明顺序或字典插入顺序均得到逐字节相同的计划。

### 回执文本格式

```text
R1|<batch_id>|<request_id>|<output_digest>
R2|<batch_id>|<request_id>|<output_digest>|<param_version>|<elapsed_ms>|<worker_id>
R3|<batch_id>|<request_id>|<output_digest>|<param_version>|<elapsed_ms>|<worker_id>|<rank>|<supersedes_ref|->|<param_digest>
```

- 段数不符：`E_FIELD/record_length`。
- 耗时、名次、摘要长度等不符：`E_FIELD`。
- 批次、请求、worker、`supersedes_ref` 无法解析：`E_REF`。
- r1/r2 补齐字段均写入 `backfilled_fields`，每个字段的来源写入 `backfill_basis`。

### 摘要绑定

参数摘要绑定 worker ID、seed、维度、参数版本和确定性 NumPy 整数矩阵。批次输出摘要绑定：

- `batch_id`
- 排序后的参与请求 ID 集合
- `param_version`
- `param_digest`
- 按请求 ID 排序的逐请求整数输出

因此同批行的处理顺序变化不会改变摘要。

### 租约与并发权益

调度器维护 `running_global` 与 `running_worker[worker_id]`，授权前同时检查全局上限和 worker quota。租约含 `lease_id`、整数 `version`、`granted_monotonic_ms`、`expires_monotonic_ms`。

- 续约必须携带读到的版本号；版本不符返回 `E_LEASE`，且不修改原到期时刻。
- 到期由 `time.monotonic_ns()` 换算的毫秒判定。
- 租约到期回收和配额下调回收都进入同一个 `_release_once_locked` CAS 入口；首个原因生效，后续回收只记录 `release_skipped`，不会重复扣减同一份权益。

### 失效与冻结

参数版本、seed、维度变化会使该 worker 的参数摘要和全部当前批次摘要依据失效；批大小或请求流变化通过成员集合和归属边界比较，只把新/变形批次及移动请求放入重算集合。

旧批次行的 `frozen_output_digest` 不被覆盖。重算会追加 receipt revision，最新 `output_digest` 可变化，而首次冻结摘要继续支撑已完成归属并可逐字节复核。

### SQLite 与快照

账本 `meta.ledger_format_version=1`，`meta.content_digest` 是除自引用摘要/快照摘要列外全部业务表的规范化 SHA-256。

批次完成时，同一事务写入：

- `batches` 批次与摘要
- `assignments` 请求归属和稳定名次
- `receipts` 回执修订
- `leases` 最终租约状态
- `invalidations` / `batches.propagation_json` 传播轨迹
- `progress.commit_cursor` 进度游标

强杀后，已提交记录保留；遗留 `running` 批次由 `mark_interrupted_batches_unknown()` 标记 `unknown`，要求重跑。程序不会声称生成了强杀瞬间的退出报告。

快照文件为 `session-snapshot/v1` JSON。恢复前先识别 `snapshot_format` 与整数 `ledger_format_version`，再重算 `tables` 摘要；不符返回 `E_SNAPSHOT`。恢复使用 `INSERT OR REPLACE` 整体替换临时库，校验通过后原子替换 SQLite 文件。

## Tkinter 页面

界面按稳定排序展示：

- 各 worker 运行数/配额水位和在途租约
- 实时排队项及等待开始/结束/当前等待毫秒
- 批次状态、unknown 标记、参数摘要、最新/冻结输出摘要
- 失效 worker、批次、请求、层级、成因和 basis
- 账本格式版本、内容摘要和快照列表

“启动实时租约演示”会复制样本到 `.runtime/ui-loopback-sample`，自动选择空闲回环端口并启动真实子进程；刷新只执行只读 SQL。

## 实测结果

本次交付在提供的 Linux 工作区执行（命令目标与 Windows PowerShell 等价）：

- `Python 3.11.0rc1`
- `numpy 1.26.4`
- `python -m pytest -q tests/test_receipt_ledger.py`：`16 passed`
- `python -m receipt_ledger --verify --runtime-dir .runtime`：退出码 `0`，报告见 `artifacts/verification-result.json`
- 原始测试输出：`artifacts/pytest-output.txt`
- 端到端运行日志：`artifacts/verification-run.log`

验证报告确认：

- 三格式 r1/r2/r3 均归一成功并带来源、补齐字段和依据。
- 计划规范化输出为 528 字节，顺序扰动后逐字节一致。
- 真实启动 3 个 `127.0.0.1` 子进程，回环 NumPy 结果与进程外重算一致。
- 调度事件峰值全局 `2/2`，单 worker 峰值未超过 quota。
- 参数版本升级后 `rb1_0c413fd714749839e9a0` 进入失效/重算集合，冻结摘要前后一致。
- 强杀 `w-gamma` 后端口关闭，遗留批次被标记 unknown，重启重跑后 3 个批次重放一致。
- 快照导出、整体恢复和恢复库重放均通过。
- `spec`、`ref`、`snapshot` 三类注入分别报告 `E_SPEC`、`E_REF`、`E_SNAPSHOT`。

当前 Linux 沙箱缺少 Tk 原生库（`libtk8.6.so` 无法打开），因此未实际弹出窗口；已通过 `python -m compileall` 和 `receipt_ledger.ui.read_only_state()` 只读状态加载检查。Windows 官方 CPython 安装包具备所需 Tcl/Tk 组件，可直接运行 `--ui`。
