一名刚加入的小组成员领取了一份尚未动工的需求：为本地 QoS 流量整形平台建立令牌桶链诊断组件，而工作区里只有一个空目录，全部代码、配置与样本都得在 Windows 本地现搭。平台管理若干整形管道，每条管道由入口、中继与出口三级串联令牌桶构成，逐事件按到达毫秒、包长与所属管道判定放行或整形；每级整形器作为 127.0.0.1 回环 TCP 上的独立子进程运行，按自身声明的令牌补充速率与突发容量对事件作出判定并回报回执。使用者会反复编辑速率、突发容量、管道串联关系与事件流，要求每次编辑后只重算真正受影响的管道与事件窗口，并在子进程被强制终止后由持久化账本恢复出可复核的放行结论。关键矛盾是：中继级余量既取决于入口放行结果又决定出口判定，任一级参数变动会沿串联链使下游窗口整段失效，而窗口边界又与到达毫秒乱序相互重叠，依赖关系跨越级别与窗口双重耦合。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pip 在命令行可用。
执行 python -m pip install numpy==1.26.4 安装唯一第三方依赖，无需数据库服务或容器环境。
在空工作区中自建样本目录，准备整形管道与整形器声明 JSON、事件流 JSON 及账本与快照输出目录，全部样本由任务参与者以固定整数种子在本地生成，不依赖外部数据或网络资源。
确保 127.0.0.1 上高位端口可被本地子进程监听，运行前清理残留进程与旧账本文件。

业务要求：
1. 实现整形管道、三级整形器声明与事件流的本地 JSON 加载及强校验：校验管道标识与整形器标识唯一、回环端口为 127.0.0.1 字面量且全局不重复、令牌补充速率为正整数、突发容量与包长为正整数、事件到达毫秒单调不减且所属管道存在；任一不合法须以 E_SPEC 报告首个非法对象标识与字段。
2. 实现三级串联令牌桶的整数定点判定：各级按经过的单调时钟毫秒以整数补充令牌并夹取在突发容量内，入口放行的事件才进入中继、中继放行才进入出口，须输出每级放行或整形结论、判定前后令牌余量、所需令牌与依据；同一事件流在任意事件分批边界下逐级判定结果必须逐字节一致，不得依赖字典遍历顺序。
3. 实现逐事件与按到达毫秒滑窗两条判定路径，并依据管道数、事件数与平均到达间隔按显式规则选择默认路径：逐事件路径独立推进各级余量，滑窗路径按窗口聚合同类事件后批量推进；须输出路径选择理由、关键规模参数与未触发切换时的边界值，当两路径预估工作量之差落在显式边界内时按稳定决胜规则选定。
4. 实现沿串联链与滑窗的失效传播与仅失效子集重算：管道串联关系、某级速率、突发容量或事件到达变更后须推导全部下游级、受影响窗口与受影响事件，按管道标识序与到达毫秒序稳定输出失效集合与每步传播依据；未受影响事件的判定结论与各级余量必须逐字节保持不变且可逐项校验。
5. 实现逐级令牌余量与整形率的整数定点统计及误差界：以配置缩放因子（10 的整数幂，允许 0 至 3）把速率、包长与余量统一量化为定点整数，补充与夹取以整数完成并显式声明截断方向与溢出饱和规则；须给出单事件量化误差、逐窗口聚合误差与三级串联累计误差上界，并区分余量差异确超容差、确未超容差与误差不可区分三类成因。
6. 实现整形器子进程编排与受全局并发上限、每管道并发配额与单次调用真实超时三重约束的并行判定调度：子进程按声明端口真实监听并通过套接字收发判定请求与回执，超时只能来自真实套接字超时；任一时刻在途调用数与单管道在途数不得超限，配额耗尽时调用排队并记录以单调时钟毫秒计量的等待起止。
7. 实现判定账本的原子落盘、版本识别整体替换与强制终止后的恢复：每次判定与每次参数版本递增须在同一 SQLite 事务中写入逐事件逐级结论、令牌余量、等待时长与进度游标，账本携带整数格式版本与内容摘要；重新打开账本时版本或摘要不一致须整体替换而非增量合并，子进程被强制终止后重启只能依据已完整提交的记录恢复，未提交批次标记为未知并要求重跑。
8. 实现独立校验命令与恢复后一致性重放校验：校验命令仅读原始声明、事件流与账本，自行重放分级判定、失效传播与定点统计并与账本逐项比较，不一致须以 E_VERIFY 定位到首个不一致的事件序号、管道、级别与字段；恢复后必须对未完成事件区间重放并与中断前已封存区间的结论逐字节比较。
