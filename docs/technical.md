# 技术说明与复算口径

## 1. 数据模型

一个样本由 64 个 `uint16` 小端文件组成，每个文件是 `256 × 256` 的空间切片，
对应一个光谱带。端元矩阵形状为 `64 × K`（默认 `K=4`），单位为
“每单位浓度的校正 DN”。生成器同时输出每个光谱带的暗场、平场、真值 JSON、
`K × 256 × 256` 掩膜文件和逐帧统计。

每个像素的光谱向量跨越全部 64 个带，因此 NNLS 必须对完整立方体求解。
报告中的“逐带指标”是对同一浓度图的每个光谱带真值位置分别评估；
校准、漂移和指标缓存仍按带组织。

## 2. 确定性

- 随机流：`numpy.random.Generator(numpy.random.PCG64(seed))`。
- 原始数据：显式 `<u2`、C order 原始字节，不使用含时间戳的压缩容器。
- 清单和记录：排序键、紧凑分隔符、禁止 NaN 的规范 JSON。
- 所有内容哈希均为 SHA-256；批次完整性另有 `audit.json` 树哈希。
- 同一配置生成两次的目录逐文件字节一致，测试同时比较树哈希和内容哈希。

## 3. 暗电流/平场校正

对每个光谱带：

```text
d = flat - dark
m = mean(d[valid])
g = d / m
corrected = (raw - dark) / g
```

`valid` 排除 `d <= flat_epsilon_dn`、`raw >= 65535` 的像素。无效像素输出
配置值 `0.0`，但同时写入 `invalid.u1` 并记录饱和、零平场、无效像素计数。
输出始终为 float32。

量化上界以一阶绝对误差传播计算。令 `e_raw,e_dark,e_flat` 的绝对值均不超过
`0.5 DN`，则每像素保守上界为：

```text
q <= 0.5 * (2/|g| + 2*|c|/|d| + |c|/|m|) + 4*eps32*max(|c|,1)
```

逐帧记录 `q` 的均值和最大值；全立方体解混使用最大值作为保守量化输入。

## 4. NNLS 与条件数

对 K 个端元，枚举所有非空活跃集 `S`（最多 `2^K-1`，本项目限制 `K<=8`），
计算 `pinv(A_S) y`。只保留全部系数非负的候选，并取残差平方最小者。
该枚举在完整列秩下与 NNLS 的 Karush-Kuhn-Tucker 活跃集解一致，且完全确定。

全矩阵 2-范数条件数为 `cond2(A)`。若超过 `cond_fatal`，抛出
`E_UNMIX_COND`；超过 `cond_warn` 时，逐像素活跃子矩阵条件数超过阈值的位置
写入 `ill_conditioned.u1`，不会删除或掩盖解。

## 5. 浓度误差区间

对像素 `p`、荧光团 `i`、活跃集 `S(p)`，定义：

```text
r_i     = ||pinv(A)_i||_2
q       = 该立方体校正量化上界
R       = 解混残差 L2 范数
Y       = 输入光谱 L2 范数
B       = 光谱带数
C_S     = cond2(A_S)
x_i     = 浓度估计

u_cal   = r_i * q
u_res   = r_i * R * sqrt(B) * 2
u_cond  = C_S * q / max(Y, 1e-12) * |x_i|
u_round = 4 * eps32 * (|x_i| + 1)
U_i     = u_cal + u_res + u_cond + u_round
interval = [x_i-U_i, x_i+U_i]
```

`sqrt(B)` 将逐带残差展开到全光谱，声明因子 `2` 是固定的约 95% 扩展；
它只放大残差分量，不改变点估计。任一像素可用
`python -m spectral_workbench inspect-pixel ...` 从缓存复算上述四项。

报告按真值掩膜汇总平均绝对误差、95 分位、超容差比例、平均不确定度和
区间覆盖率。首次超容差像素按光谱带升序、像素 C-order 查找，并附四项分解。

## 6. 漂移估计与补偿

对每个光谱带，以真值清单中的参考中心为窗口中心。窗口半径为
`min(配置半径, 0.4 × 最近中心间距)`。窗口内减去指定背景分位，使用正权重
质心得到亚像素中心；峰值低于 `min_center_signal_dn` 的中心不参与平均，
并仅保留强度不低于最强候选 25% 的中心。估计平移是这些中心位移的均值。

估计值与真值 `drift_xy` 比较得到残差。估计范数超过 `max_shift_px` 时抛出
`E_DRIFT_BIAS`。补偿按 `out(x,y)=in(x+dx,y+dy)` 做双线性采样；
越界和插值无效像素显式计入最终无效掩膜。

## 7. 增量缓存与闭合

缓存根目录为 `<run>/cache`，每个版本目录保存输入、配置和输出哈希。

| 阶段 | 键的主要内容 | 复用边界 |
|---|---|---|
| calibration | raw/dark/flat 哈希 + 校正配置 | 每个光谱带独立 |
| drift | 全部校正哈希 + 参考中心 + 漂移配置 | 整段估计，结果复用 |
| unmix | 全部带/补偿/无效掩膜版本 + 端元哈希 + 解混配置 | 立方体级全局解 |
| metrics | unmix 版本 + 该带真值哈希 + 容差 | 每个光谱带独立 |

端元或解混阶数变化会改变全局 NNLS 输入，因此全部光谱带都被正确标记为受影响；
校正、漂移仍复用。补偿开关变化时，原始未补偿 NNLS 缓存可被复用。
若校正配置变化但输出内容未变，下游仍按内容哈希复用。

运行报告逐帧记录 `source=computed|reused` 与版本哈希。`--verify-closure`
绕过缓存全量重算校正、漂移、补偿和 NNLS，按声明容差比较；任何分歧抛出
`E_CLOSURE_MISMATCH`，详情包含阶段、光谱带、像素和数组索引。

## 8. 快照与 UI

快照只读数组包括伪彩帧、等距频带位置、浓度曲线、误差上下界、病态带标记和
病态像素掩膜。快照哈希覆盖版本、来源 run hash、元数据和所有数组的
dtype/shape/内容哈希。`SnapshotStore` 只接受更高版本；视图渲染前必须匹配当前
版本和内容哈希，否则抛出 `E_SNAPSHOT_STALE`。

`DiagnosticWindow` 不持有管线或服务对象，只接受已发布快照。参数变化只能由
服务显式重算并发布新版本，UI 没有重算入口。

## 9. 业务错误码

| 错误码 | 触发点 |
|---|---|
| `E_CUBE_FORMAT` | 清单/尺寸/哈希错误，饱和比例超输入策略 |
| `E_DARK_GAIN` | 暗场最大值越界、零平场比例过高、平场均值无效 |
| `E_UNMIX_COND` | 端元退化、非有限、零范数、条件数超致命阈值 |
| `E_DRIFT_BIAS` | 估计平移超容差 |
| `E_CLOSURE_MISMATCH` | 增量与全量重算不一致 |
| `E_SNAPSHOT_STALE` | 快照陈旧、版本未递增或哈希损坏 |
| `E_INJECT_CONFIG` | 注入/参数范围或字段非法 |

CLI 将错误以 JSON 写入 stderr，并返回固定退出码：10–16 分别对应上表顺序。
