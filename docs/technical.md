# 技术设计与一致性说明

## 1. 对齐对象

任务输入描述的是“序列库”，但 DTW 必须比较两条序列。为避免隐藏全局状态，本实现通过 YAML 的可选 `reference_sequence_id` 显式指定库内参考序列；每个有效序列形成独立任务：

```text
query = 当前序列（行方向）
reference = reference_sequence_id 指向的序列（列方向）
```

未配置参考 ID 时退化为查询序列与自身对齐。样本使用 `S00` 作为参考；修改参考点会使所有任务的目标键变化，而修改普通查询点只影响其自身任务。

## 2. 定点与带状约束

可行域按行保存闭区间 `[col_start, col_end]`。中心使用整数运算 `round_half_up(i*(m-1)/(n-1))`，避免浮点舍入分歧。带宽半径为 `ceil(max(n,m)*permille/1000)`。首末单元强制保留，确保存在端点连通的候选范围；是否真正连通仍由 DP 判定，失败返回 `E_NO_PATH`。

量化首先将物理值映射到定点网格，再按 `quantization_step` 个最小单位取整。`Decimal` 从字符串构造，避免二进制浮点把同值映射到不同边界。残差是同步持久化的精确字符串，因此切换档位时定点整数和残差均可审计。

## 3. DP 单元契约

`CellProduct` 持久化以下内容：

- 坐标、局部代价、累计代价、是否可达
- 回溯标签与回溯坐标
- 可行前驱坐标和全部名义前驱条目
- `local_key`、`band_step_key`、`cache_key`、`content_key`
- 稳定 `task_key = cell:<sequence_id>:<row>:<col>`
- 读取的 query/reference 点索引

固定前驱优先级通过顺序列表和严格比较实现。对称模式为三条；非对称模式为两条，并按查询/参考长度方向选择可连通的两步模式。所有累加均为 Python 任意精度整数。

## 4. 精确失效

对每个新可行单元 `(i,j)`，规划器依次检查：

1. 旧可复用缓存中是否已有该坐标；否则 `NEW_FEASIBLE_CELL`。
2. 用旧量化/旧配置与新量化/新配置重算 `local_key`；不同则 `LOCAL_POINT_CHANGED`。改变点 `p` 只可能直接命中 `i=p` 或 `j=p`。
3. 比较新可行前驱集合与旧单元记录；不同则 `PREDECESSOR_SET_CHANGED`。
4. 比较此行带区间和步进规则派生的 `band_step_key`；不同则 `BAND_STEP_KEY_CHANGED`。
5. 步进模式改变时整体标记 `STEP_MODE_CHANGED`。
6. 从所有直接失效单元沿新可行图的“前驱 → 后继”边传播 `DOWNSTREAM_OF_INVALID`。

旧可行而新不可行的坐标进入 `removed_cells`。其余坐标直接复制旧 `CellProduct`。由于每个新单元的局部键、前驱集合和前驱内容都未变化，复用的代价与回溯指针可证明等价于重算结果。原则上只需重算“直接失效集合 ∪ 其下游”；不再访问任何无关单元。

序列级目标键还包含两条记录、双侧量化内容、带指纹、对齐参数、最大路径长度与策略。目标键未变时，直接复用整条持久化结果，连单元遍历也省略。

最终结果再输出 `path_key` 与 `segment_key`：前者由量化/带/对齐指纹、单元格内容清单和路径代价派生，后者由 `path_key` 与分段明细派生；`result_key` 组合二者，便于独立审计路径或分段缓存是否变化。

## 5. 批预算与待办

批次开始时记录上一批所有未完成序列 ID。编辑按计划顺序应用后：

1. 计算每个序列的新目标键与失效集合。
2. 上批待办序列优先，然后按序列 ID 排序。
3. 冻结本批预算 `B`，按序分配：需求不超过剩余预算则全量分配；否则只分配剩余值，并把此序列及之后的序列置为待办。
4. 仅将已得到正配额且彼此独立的序列任务提交到最多 `thread_pool_workers` 个线程。
5. 每个序列内部按行号、列号升序计算已分配前缀；完成全量后回溯路径。

待办序列以 `E_CELL_BUDGET_PENDING` 写入本批异常；工作产物（已复用单元 + 已重算前缀 + 剩余坐标）随后进入原子快照。下一批从快照恢复后继续同一目标；如果新编辑改变目标，则以最近已提交结果重新规划，避免混合两代缓存。

因为预算分配在提交线程之前完成，线程调度不会改变单元格由哪个批次消费。输出合并、失败清单和账本追加均在主线程按稳定 ID 顺序完成。

## 6. 快照与恢复

`latest.json` 每批以“临时文件 + `os.replace`”原子提交。配置的 `snapshot_interval_batches` 控制不可变归档副本。快照包含：

- 当前配置与有效/无效序列装载状态
- 每个序列的 `committed` 结果与可能的 `working` 待办
- 量化序列、带区间、全部已持久化单元、路径、分段和失败
- 批次、预算、失效、复用、编辑异常账本

演示在每批后销毁内存对象并从 `latest.json` 重建引擎，再继续下一批。因此最终一致性验证实际覆盖了磁盘序列化、反序列化和跨批复用。

## 7. 等价性判定

`canonical_equivalence` 比较三个字段：

- `sequences`: 按序列 ID 排序的完整对齐结果，包括路径、总代价、全部单元记录、分段、带信息与失败
- `failures`: 规范排序后的活动失败清单
- `pending_sequences`: 最终未完成序列；验证要求为空

全量参考使用最终配置与最终有效序列库从空缓存重算，不受操作预算限制。并发/串行对照还分别比较预算账本、失效账本和复用账本。

## 8. 边界与策略

- `path_length_policy=reject`: 返回拒绝状态、原始总代价和 `E_PATH_LENGTH_REJECTED`，不伪造合法路径。
- `path_length_policy=truncate`: 输出前缀路径、前缀代价，并保留 `raw_total_cost` 与 `W_PATH_TRUNCATED`。
- 缺失点使用固定整数罚分，不参与普通差值。
- `reference_sequence_id` 不在有效库中时记录 `E_SEQUENCE_NOT_FOUND`，并明确退化到自对齐，不静默隐藏配置问题。
- 最终 `failure_list.json` 只含当前状态异常；历史编辑异常位于 `edit_failure_ledger.json`。
