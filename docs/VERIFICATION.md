# 固件分区映射审计引擎 — 技术说明与验证记录

## 1. 运行环境

- Python 3.11（开发验证版本 3.11.0rc1，要求 >= 3.11）
- 仅依赖标准库；测试依赖 `pytest`（验证环境 9.2.0）
- 不使用容器、网络账号或外部镜像；样本全部由 `fwaudit/generator.py` 现场确定性生成

### 环境准备（Windows / Linux 一致）

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install pytest
mkdir samples reports
```

离线工作站若 `ensurepip` 不可用，可使用管理员预置的 get-pip 引导或离线 wheel：
`python get-pip.py` 后 `python -m pip install pytest --no-index --find-links <wheel 目录>`。

## 2. 二进制格式约定（实现口径）

### 2.1 镜像头（32 字节）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | 魔数 `FWIM` |
| 4 | 2 | 格式版本 uint16 LE，白名单 {1,2} |
| 6 | 4 | 分区数量 uint32 LE |
| 10 | 8 | 分区表偏移 uint64 LE |
| 18 | 8 | 镜像声明总长 uint64 LE |
| 26 | 6 | 保留区（见下） |

题面文字写“保留区 8 字节”，但 4+2+4+8+8=26，32 字节头实际只剩 6 字节，
实现以 32 字节硬约束为准。保留区编码：基镜像标识 uint32 LE（偏移 26）、
基镜像槽位 uint8（偏移 30）、末尾保留字节必须为 0（偏移 31）。

### 2.2 分区描述记录（固定 20 字节 + 名称）

`u16 名长 | u8 类型 | u8 槽位 | u64 载荷偏移 | u64 载荷长度 | 名称 UTF-8`

- 类型白名单 {0,1,2,3}，槽位白名单 {0,1}
- 载荷偏移+长度做 64 位溢出检查，且区间不得越过镜像声明总长
- 载荷侵入头部在解析期直接判 `E_PART`；覆盖分区表描述区判 `E_SELFREF`

### 2.3 补丁头（16 字节）与操作记录

补丁头：`FWIM | u16 版本(白名单{1}) | u32 操作数 | u32 基镜像标识 | u16 保留(必须 0)`。
题面字段合计 14 字节，剩余 2 字节实现为保留区以满足 16 字节硬约束。

操作记录：`u16 名长 | u64 写入偏移 | u32 写入长度 | 名称 | 32 字节摘要`。
写入偏移/长度以**目标分区载荷起点为原点**（相对偏移），引擎同时换算绝对镜像
区间以识别对头部/分区表描述区的覆盖。

### 2.4 真值同步标记（128 字节，`FWT1`）

每个分区载荷首部写入：魔数、分区名、槽位、载荷区间、载荷体声明摘要。
验证端 `fwaudit/verify.py` 只信任该标记与确定性重算结果，不信任分区表重复声明；
载荷体由 `sha256(名称派生种子, 计数器, 载荷偏移)` 确定性填充，可逐字节复算。

## 3. 业务码

| 业务码 | 触发条件 |
|---|---|
| E_HEADER | 镜像头魔数/版本/长度自洽/保留区非法 |
| E_PART | 分区记录越界、UTF-8 非法、白名单、64 位溢出 |
| E_OVERLAP | 任意两分区载荷部分交叉或包含（输出名称对与关系） |
| E_SELFREF | 载荷覆盖分区表描述区（头部侵入在解析期判 E_PART） |
| E_PATCH_HEADER | 补丁头/操作记录解析与文件长度不自洽 |
| E_PATCH_BOUNDS | 目标分区不存在或写入越过分区/描述区边界 |
| E_SLOT_ESCALATION | 目标分区槽位与补丁基镜像槽位不一致 |
| E_WRITE_CHAIN | 同分区多操作归一化合并后跨界或覆盖描述区 |
| E_STALE_BASE | 基镜像标识或格式版本相对最新代次变化 |
| E_TIMEOUT / E_OPS | 真实计时超时 / 超单补丁操作上限 |
| E_LOCK | 工作目录文件锁冲突（非阻塞） |
| E_ARGS / E_UNKNOWN | 参数错误 / 无基镜像等兜底 |

## 4. 关键语义

1. **结构冲突与物理顺序无关**：重叠检测按分区名排序后两两比较，输出确定。
2. **写链归一化**：按 (起点, 终点) 排序合并，参与操作序号同步排序，
   逆序导入得到相同链；链结论携带操作序号与合并区间端点（相对+绝对）。
3. **换代失效传播**：以镜像代次水位为准，补丁导入时记录所依据的
   `(基镜像标识, 格式版本)`；审计时与最新代次比对，任一不同即 `E_STALE_BASE`，
   失效补丁逐操作标记 `skipped_stale`，覆盖率记 0。镜像/补丁任意交错导入，
   引擎统一先收齐代次再下结论，最终失效集合一致。
4. **规模策略**：镜像字节数或补丁操作数超阈值即进入分块降级，
   仅校验完整分块，报告 `degraded/coverage_ratio/uncovered_ops`，
   未校验操作状态为 `skipped_degraded/skipped_timeout/skipped_ops_cap`，
   绝不报告为通过。
5. **批隔离**：单补丁解析/预算失败只影响自身；线程池并发审计，异常被收敛为结论。
6. **检查点**：`checkpoint.json` 记录代次水位与聚合结论；
   结构版本或策略版本变化即整体重建。所有输出走“同目录临时文件 + os.replace”，
   并发以 `fcntl`/`msvcrt` 锁串行化，锁冲突返回 `E_LOCK`。
   强制终止不承诺退出报告（仅保证已完成检查点的原子性）。

## 5. 报告与退出码

- `reports/audit_report.json`：文件级结论、每分区映射状态、每补丁每操作状态、
  业务码、出错偏移、降级覆盖、真值校验与聚合 summary。
- `reports/partition_map.json` / `.txt`：分区节点、槽位标记、越权链/槽位/重叠边。
- 退出码：`0` 全部成功；`1` 部分失败；`2` 参数错误。

| 场景 | 预期业务码 | 实测 |

| good.fwdf（界内写） | E_OK | pass, coverage 1.0 |
