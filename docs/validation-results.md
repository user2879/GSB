# 本地验证结果

验证日期：2026-11-19

执行环境：Ubuntu 22.04 / Python 3.11.0rc1（任务提供的离线工作区）。运行时实现只使用跨平台标准库，并为 Windows 增加路径保留名检查、大小写冲突检查、Windows PID 存活检查与盘符/UNC 拒绝逻辑。

## 1. 自动测试

命令：

```bash
python -m unittest discover -s tests -v
```

结果：`Ran 18 tests ... OK`。测试集同时可由 pytest 通过 `pytest -q` 发现和执行（本环境未安装 pytest，未联网安装额外包）。

覆盖项：

- 非法条目逐条拒绝但合法条目继续恢复；输入 JSON 摘要前后不变；
- 同批一个损坏 JSON 不会中断其他合法恢复请求；
- 指纹断裂、前驱指纹不匹配、自引用、双节点环及到达顺序无关性；
- 同前驱双分支 `E_FORK`，所有完整分支指纹保留，仅共同前缀提交；
- 持久化水位回滚、显式旧快照重放 `E_ROLLBACK`，状态不回退；
- `E_TAMPER`、`E_LENGTH` 排除集合与后续合法快照重新写回；
- HMAC-SHA256 成功路径与算法白名单收窄重建；
- 活锁/不可读锁返回 `E_LOCK`，死进程锁回收；
- 5 个原子写入中断点强杀，旧检查点仍完整，恢复后无临时文件；
- 乱序导入多排列的报告与状态逐字段一致；
- 检查点结构版本变化、策略变化、恢复代际损坏后的整体重建；
- 内容寻址库文件名与内容指纹不一致检测；
- 样本生成器两次输出逐文件摘要一致。

## 2. CLI 样本演练

样本由以下命令生成：

```bash
python -m backup_engine samples --output samples
```

本次生成的场景包含 `valid/`、`fork/`、`tamper/`、`chain_break/`、`fingerprint_mismatch/`、`cycle/`、`self_reference/`。

| 场景 | 退出码 | 业务码 | 生效版本 | 关键结果 |
|---|---:|---|---|---|
| 有效三版本链 | 0 | 无 | 1, 2, 3 | 水位 3；`status` 与 `verify-checkpoint` 均成功 |
| 指纹断链 | 1 | `E_CHAIN_BREAK` | 1 | 仅共同前缀生效 |
| 前驱指纹不匹配 | 1 | `E_FINGERPRINT` | 1 | 报告实际计算前缀 |
| 双节点环 | 1 | `E_CYCLE` | 无 | 不提交环内状态 |
| 自引用 | 1 | `E_CYCLE` | 无 | 不提交自引用状态 |
| 同前驱分叉 | 1 | `E_FORK` | 1 | 2 个完整分支标识均保留 |
| 篡改条目 | 1 | `E_TAMPER`, `E_LENGTH` | 1, 2 | 排除 `README.txt`、`data/a.txt`、`data/b.txt`；`data/nested/keep.txt` 与 `data/valid.txt` 仍恢复；水位 2 |
| 水位回滚 | 1 | `E_ROLLBACK`, `E_FORK` | 原状态 | 回滚版本 2，已提交水位保持 3 |
| 显式旧版本重放 | 1 | `E_ROLLBACK`, `E_FORK` | 原状态 | 回滚版本 2，已提交水位保持 3 |
| 活锁冲突 | 1 | `E_LOCK` | 无 | 未产生检查点 |

乱序一致性验证：

- 对同一有效快照集合采用 3 种导入顺序；
- `recover` 报告逐字段相等：`true`；
- `status.state` 逐字段相等：`true`；
- 最终排除路径集合相同且为空。

原子写入与强杀验证：

- 子进程在“恢复代际已写、检查点尚未切换”处退出，退出码 94；
- 强杀后旧检查点仍可校验，水位保持 1，只能看到版本 1 状态；
- 再次恢复后水位推进到 2；
- 清理/恢复完成后 `*.tmp-*` 文件数量为 0；
- `checkpoint.json` 与恢复代际文件均等于规范 JSON 字节。

## 3. 结论

本地样本验证了任务验收要求的五条主路径：指纹链校验、篡改排除、回滚/分叉判定、检查点恢复及原子快照写入。恢复结论、条目顺序、排除集合和分支集合在乱序导入下保持一致；强杀不会暴露半写恢复状态，也不会承诺生成退出报告。
