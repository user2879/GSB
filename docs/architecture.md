# 多光谱瓦片地物分类工作台 — 技术说明

## 1. 总体架构

工作台以纯 Python 包 `mstc` 交付，按“加载校验 → 逐瓦片定点分类 → 重叠带加权投票 →
连通域后处理”四个阶段组织，并由缓存/快照层与预算调度器横向支撑。所有数值热路径仅使用
带符号 64 位整数定点运算，浮点仅出现在诊断模块的双精度参考实现中。

模块职责：

- `errors.py`：稳定业务码与顺序确定的失败清单（单瓦片故障不中断其它瓦片）。
- `paths.py`：Windows 风格相对路径（反斜杠）到原生路径的唯一转换点，保证配置在
  Linux/macOS/Windows 行为一致。
- `fixedpoint.py`：定点引擎（小数位宽 + 量化档位）、整数开方、定点乘除、舍入方向、残差。
- `config.py`：YAML 配置加载与全部枚举/预算/权重校验。
- `model.py`：类别编码、波段集合版本（BS_V1/BS_V2）、瓦片与清单数据模型。
- `samplegen.py`：固定种子确定性样本生成（全局连续潜类场 + 每瓦片独立传感器噪声）。
- `loader.py`：清单解析与逐瓦片校验，输出业务码失败清单。
- `features.py`：窗口级 NDVI / NDWI / 纹理梯度 / 高程坡度定点特征与量化记录。
- `classifier.py`：中心区域归属的窗口划分、固定顺序打分、低分同票决断、整数概率、缓存键。
- `fusion.py`：相邻瓦片重叠带加权投票（FV1/FV2 两套真实不同规则）、平票字典序决断、融合指纹。
- `postprocess.py`：全局栅格拼装、4 连通碎块剔除与邻接主类别回填。
- `snapshot.py`：两级缓存与阶段临时目录 + 整目录原子替换、版本/配置哈希陈旧判定。
- `scheduler.py`：全局像素预算、单瓦片配额、融合批次上限三重约束与线程池稳定排序。
- `diagnostics.py`：双精度参考投票、半步阈值边界诊断、`E_BOUNDARY_FLIP` 归因。
- `injection.py`：独立注入配置、沙箱副本故障注入、注入编号到业务码的命中报告。
- `pipeline.py`：编排全流程、精确增量失效、诊断与快照清单写入。
- `report.py` / `cli.py`：诊断报告序列化与命令行入口。

## 2. 定点确定性与量化档位

`FixedConfig(fractional_bits, gear)` 决定表示：内部缩放因子为 `2^fractional_bits`，
量化档位 `FINE/NORMAL/COARSE` 再分别附加 0/1/2 位右移。因此切换档位会真实改变每个
中间整数与类别得分（测试 `test_quantization_gear_changes_scores` 断言）。每次量化都记录
残差（以微单位 1e-6 编码的整数）与舍入方向（-1 向下 / 0 精确 / +1 向上）。

特征按固定运算顺序计算：NDVI=`(NIR-R)/(NIR+R)`、NDWI=`(G-NIR)/(G+NIR)`、纹理为红波段
梯度均值的整数开方、坡度为高程差分的整数开方。打分严格按
WATER、VEGETATION、BUILT、BARE 的顺序累加，同分时 `argmax_tie_low` 取最低类别编码。

## 3. 中心区域归属（避免重复计数）

`window_origins` 以步长 `stride` 生成互不重叠且完整覆盖瓦片的中心区域；越界窗口向内夹紧，
特征提取使用复制填充。每个像素恰好被一个窗口拥有，测试断言覆盖完整且归属计数恒为 1。

## 4. 重叠带融合与融合策略版本

仅融合 `right/down` 方向，保证每对相邻瓦片处理一次。每个重叠像素两侧各投一票：

- FV1：前向几何距离 × 类概率（近侧瓦片权重更高）；
- FV2：概率置信度平方、几何中性化（更自信的瓦片即使更远也可胜出）。

两者是真实不同的加权规则，在确定性样本上产生 128 处投票翻转与不同的全局栅格。平票按
行列字典序扫描、再按最低类别编码决断。融合指纹由两侧瓦片缓存键、概率摘要、重叠几何与
策略版本派生。

## 5. 精确增量失效

- 瓦片缓存键 = SHA256(波段内容指纹 | 波段集合版本 | 指数权重/定点/窗口指纹)。
- 融合指纹 = SHA256(两侧缓存键 | 两侧概率摘要 | 重叠几何 | 融合策略版本)。

波段补丁只失效对应瓦片及其参与的融合带；权重/定点变化使全部瓦片失效；邻接或瓦片增删改变
参与的融合对。未受影响项命中缓存且不重算（见 `test_band_patch_only_invalidates...`）。

## 6. 三重预算调度

- 全局像素预算不足 → 未完成瓦片记 `E_PIXEL_BUDGET_EXHAUSTED` 并保留待办；
- 单瓦片配额超出 → 该瓦片记 `E_TILE_BUDGET_EXHAUSTED`；
- 每批融合重算受 `fusion_batch_limit` 约束，超出记 `E_FUSION_BUDGET_PENDING`，下一批优先。

线程池大小取自配置且不超过待办数；任务携带由阶段名+行列号+瓦片号派生的稳定排序键，
结果在收集时按该顺序重排，因此并发与串行逐像素一致。

## 7. 阶段化快照与恢复

每阶段产物先写入 `tmp.<pid>/`，再通过 `os.replace` 整目录原子替换，绝不逐文件覆盖已提交
内容。快照清单记录全局版本号、配置哈希、波段集合版本、融合策略版本、已完成瓦片与已消耗
配额。启动时版本号或配置哈希不一致即记 `E_SNAPSHOT_STALE` 并从受影响阶段重建。

## 8. 边界诊断与异常注入

边界诊断对“最高与次高投票分差 ≤ 量化半步（按投票量级缩放）”的像素，计算双精度参考投票、
定点判定与差异方向；判定不一致记 `E_BOUNDARY_FLIP` 并给出归因。注入在一次性沙箱副本上
施加截断文件、缺失波段、悬空邻接、非有限权重、窗口不整除、分辨率不符六类真实故障，
注入编号与业务码一一映射，单瓦片失败不影响其余瓦片。
