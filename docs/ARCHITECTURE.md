## 2. 双路径判定

### 精确路径（exact）
逐分钟维护长度为 `window_minutes` 的分钟环形缓冲，每分钟 O(1) 滑动累计
窗口内成功/失败整数，结论为权威值。

### 分块增量近似路径（incremental）
- 块边界对齐绝对分钟 `minute // chunk_capacity`，迟到/重放确定；
- 完整密封块只保留块级合计并被窗口整体复用；
- 活动块按分钟明细精确展开；
- 每步先回收离窗块再纳入当前分钟，复用上一分钟窗口状态。

### 显式路径选择规则
同时满足以下三条才默认增量路径，否则精确路径：
1. `window_minutes >= 60`；
2. `batch_count >= 12`；
3. 增量状态占比 `chunk_capacity / window_minutes <= 0.5`。

### 偏差界（量化依据）
近似仅来自与窗口部分相交的密封边界块：
- `|Δtotal| <= 边界块落在窗口外分钟的请求量`；
- `|Δfailures| <= 同上失败量`；
- `|Δremaining| = 10000 * |Δtotal|`（整数恒等式）；
- 燃烧率以精确分式为中心，按 total/failures 整数扰动给出分式区间。

## 3. 迟到批与稳定去重
- 窗口引用关系：分钟 `m` 被窗口终点 `t ∈ [m, m+W-1]` 引用；
- 后到（late 流）按稳定规则覆盖先到，同流内按 `(line, batch_seq)` 择一；
- 每次覆盖写入 `coverage`，受影响集合按 `(service_id, minute)` 稳定排序。

## 4. 租约与裁决
- 评估器是独立子进程，AF_UNIX 长度前缀 JSON 帧，`time.monotonic_ns` 真实计时；
- 租约含授予/到期毫秒与版本号；续约凭版本号乐观校验，不符抛 `E_LEASE` 且不延期；
- 全局槽位上限与每服务租约上限由权威强制；
- 裁决事件按 `(时间, 槽位, 服务, 原因, 来源序号)` 全序化，任意输入顺序得到同一序列；
- 同一租约只能被 expiry 或 revoke 回收一次，第二次记 `rejected-double-count`。

## 5. 账本与恢复
- 所有写入在单 SQLite 事务内 `COMMIT`，携带整数格式版本与 SHA-256 摘要；
- 参数版本按生效区间划分，旧版本结论标记 `stale=1` 不参与展示；
- 快照版本/摘要不一致走 `replace_all` 整体替换，禁止增量合并；
- 强制终止后只恢复已提交行；`pending_batches` 标 `unknown`，重跑前回收租约配额；
- 系统不生成强制终止时刻退出报告。
