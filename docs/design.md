# 设计说明

## 可重放结论与执行侧数据

可重放结论只包含由最终配置、事件和确定性样本派生的字段：聚合摘要、权威回执、水位、就绪结论、业务码、预算、批计划、游标以及内容判决账本。真实耗时、节点进程代数、原始节点应答和进程内账本放入 `execution`，用于审计但不参与重放比较。

逻辑租约代次由分片修订号确定并进入缓存键，使未受影响分片保持稳定；节点进程内的租约代次则按每个节点真实单调递增，并在每个应答中返回。两套代次都可在报告中复核，前者保证跨运行逐字段一致，后者证明真实租约状态机。

## 状态归约

所有事件从声明基线顺序归约。批次增删改提升分片修订号；分片替换可保留或改名；依赖改写只修改目标分片；配额新增必须显式引用已存在父版本；回滚只切换到既有版本；容量调整进入节点覆盖层；位宽切换进入最终位宽。归约完成后再次检查活跃配额、节点、依赖拓扑与分片引用。

## 依赖与预算

拓扑序采用确定性最小堆：每轮从零入度分片中选择最小标识。派发前检查上游权威摘要；若上游失败或缺失，分片进入待办队列并记录 `blockers`。全局预算按 `ceil(points / points_per_resource_unit)` 计费；单批超限拒绝单分片，累计超限开启新批。

## 租约回收

节点状态不是“到期即视为释放”的布尔标记。`sweep` 在锁内遍历有效租约，删除到期项、记录租约和被回收分片、写入 `E_LEASE_EXPIRED`，随后容量计数立即允许新租约。重复过期请求通过已回收租约索引返回 `E_LEASE_EXPIRED`，不会退化成不存在。

## 原子账本

提交过程为：

1. 在 `ledger/snapshots/.staging-*` 写完整阶段产物、队列、租约与校验和。
2. 对关键文件执行 `fsync`。
3. 将临时目录原子改名为不可变快照目录。
4. 将新 `CURRENT` 指针写入临时文件并 `fsync`。
5. 原子替换 `CURRENT`。

读取端只认 `CURRENT` 指向的快照，并校验 `global_version`、基础配置哈希和 `ledger.json` 校验和，因此不会把半写文件当成有效状态。

## 定点误差归因

参考路径使用比活跃位宽高一位的完整聚合。诊断逐分片比较每组每维的 `quantized_sum`，记录首个差异分组、维度、差值和差异维度数量。水位使用同一资源量分别以活跃/参考位宽计算软硬上限；就绪结论则比较活跃阻塞来源与最终权威上游是否存在。首个超差阶段按 `aggregate_quantization`、`watermark_rounding`、`dependency_decision` 顺序固定，并将总体来源聚合到 `aggregate_rounding`、`watermark_rounding` 或 `dependency_chain_change`。
