当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个面向 Windows 本地环境的中间件配额仲裁工作台，场景是服务注册与健康探测：多个租户共享一组本地模拟服务实例，实例以回环 TCP 上的确定性服务子进程表示，探测结果驱动实例健康判定，而健康判定又决定仲裁授予哪些租户的请求。用户在本地 JSON 文件中声明租户（租户标识、整数配额份额、整数并发请求上限、整数突发额度）、服务实例（实例标识、127.0.0.1 回环端口、整数权重）、探测策略（探测间隔毫秒、连续失败阈值、单次探测超时毫秒）与仲裁规则版本；本地 NDJSON 请求流逐行给出请求标识、租户标识、整数资源需求与整数毫秒到达时刻。工作台须在受全局并发上限与每租户并发配额约束下并行处理请求，同时按真实套接字探测维护实例健康状态，并把探测判定、仲裁结局与配额账本演进固化为可复核记录。

任务环境与准备：
确认 Windows 本地具备 Python 3.11 及以上解释器，并可使用标准库 sqlite3、socket、subprocess、threading 与 tkinter。
安装 NumPy（用于确定性样本与聚合验证），并提供 pip 安装说明；不引入其他第三方依赖，不使用容器或线上服务。
准备本地 JSON 租户与实例声明、NDJSON 请求流、确定性样本生成脚本与 Tkinter 演示脚本，全部使用 127.0.0.1 回环高位端口，不依赖真实账号或外部站点。
验证前预留若干空闲回环端口，并确认可启动本地子进程模拟服务实例；端口占用场景通过参数注入构造。

业务要求：
1. 实现租户、服务实例、探测策略、仲裁规则与请求流的加载及强校验：从本地 JSON 读取租户、实例、探测策略与规则版本，从 NDJSON 逐行读取请求，校验租户标识与实例标识唯一、端口为 127.0.0.1 回环字面量且全局不重复、配额份额为非负整数、请求到达时刻单调不降、资源需求为正整数、请求引用的租户存在；任一不合法须以 E_SPEC 整体拒绝加载并稳定列出首个违规字段与行号。
2. 实现本地模拟服务实例的确定性编排与真实健康探测：以 Windows 子进程按实例声明在回环端口启动服务，可按参数注入正常应答、连接拒绝、响应延迟、错误返回四类行为；探测结果只能来自真实套接字连接与响应，成功与失败判定不得由人为等待推断，单次探测超时须由真实套接字超时产生；实例在 unknown、healthy、unhealthy、ejected 间迁移，每次迁移记录触发探测轮次、连续失败累计与单调时钟毫秒。
3. 实现受双重预算约束的请求仲裁调度：在全局并发上限与每租户并发配额同时生效下推进请求仲裁，任一时刻在途请求数与单租户在途请求数不得超限，配额耗尽时请求排队并记录等待开始与结束的单调时钟毫秒；仲裁仅授予健康实例所承载的租户，实例处于 unhealthy 或 ejected 时其承载租户的请求须按显式规则转为排队或拒绝，且不得绕过配额继续授予。
4. 实现配额账本的逐请求仲裁结局与三态演进：每条请求在授予、排队、拒绝三态间按显式判决顺序推进，判决须依次考虑租户剩余配额、租户在途数、租户突发额度与目标实例健康状态并记录所用依据；授予须实时扣减配额并占用在途，拒绝须记录触发条件；同一请求在同一输入与同一规则版本下多次执行必须得到逐字节一致的结局与依据序列。
5. 实现探测判定与仲裁结局之间的依赖失效传播：租户仲裁结论、实例可选集合与健康统计均由探测判定与实例权重派生，须建成有向依赖关系并校验引用完整；当某实例探测迁移、实例集合变化或规则版本演进时，沿依赖关系推导全部直接与间接受影响租户与请求，按稳定顺序输出受影响集合与每步传播依据，未受影响请求的结局与依据序列必须逐字节保持不变且可逐项校验。
6. 实现账本持久化与强制终止后的恢复：每完成一个仲裁批次或一次探测迁移须在同一 SQLite 事务中写入请求结局、依据、租户配额余量、在途数、实例健康状态与进度游标，账本携带整数格式版本与内容摘要；进程被强制终止后重启只能依据已完整提交的记录恢复，处于在途且未提交的请求须标记为未知并要求重跑，不得声称能生成强制终止时的退出报告。
7. 实现会话快照的版本识别与整体替换恢复及恢复后重放校验：快照持久化租户集合版本、实例集合版本、探测策略版本、仲裁规则版本、配额终态与已完成请求游标并携带内容摘要；重新打开快照时须比较快照版本与内容摘要同当前声明是否一致，不一致须整体替换租户、实例与账本状态而非增量合并，替换须稳定列出差异项；恢复后按记录重新执行探测与仲裁，将每条请求结局、实例健康迁移与配额终态同账本逐项比较，差异须定位到首个不一致的请求标识、租户与字段并以 E_REPLAY 报明依据。
8. 实现异常注入、结构化日志与 Tkinter 诊断界面：支持以命令行参数分别注入实例端口占用、租户配额份额之和超出声明上限、快照内容摘要不符三类异常，分别以 E_PORT、E_QUOTA、E_SNAPSHOT 业务码报告并写入结构化日志，注入仅改变输入文件或参数；界面展示租户配额余量与在途数、实例健康状态与迁移理由、探测轮次、请求结局分布、受影响集合、当前版本与快照列表，渲染顺序稳定且刷新不改变账本内容。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

使用本地确定性租户、实例与请求样本验证仲裁结局、健康迁移、账本恢复与重放校验结果一致。
