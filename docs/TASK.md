方案讨论阶段已结束，代码尚未动笔，工作区里只有一个空目录，需要在 Windows 本地交付一个面向构建流水线制品缓存的跨节点租约仲裁中间件组件与可重复示例。与逐条登记制品并判定缓存命中不同，本组件把缓存复用视为一种可被多个流水线运行临时持有的租约资源：用户在本地 JSON 中声明若干缓存节点（节点标识、127.0.0.1 回环端口、整数容量槽位、整数每节点租约上限、整数随机种子）与一条构建流水线清单（阶段、制品键、制品间引用以及各阶段并发配额），制品以本地文件形式存放在工作区。组件须在回环 TCP 上以子进程托管缓存节点，按制品键向节点申请租约，并回答哪些制品可复用、哪些必须重算、租约到期后容量如何回收，且结论在任意编辑后增量推进与中断恢复后与全量重建逐字段一致。

任务环境与准备：
安装 Python 3.11 及以上版本，并在命令行确认 python 与 pip 可用。
执行 pip install numpy 安装 NumPy，用于确定性制品摘要与容量核算的数值部分。
确认 Tkinter 随 Python 发行版可用（可用 python -c "import tkinter" 自检），无需额外安装图形库。
在工作区新建项目目录，确认 127.0.0.1 的若干高位端口可绑定，且本机未运行占用这些端口的本地服务。
以 UTF-8 保存本地 JSON 声明文件与流水线清单，所有时间字段以整数毫秒表示，时间基准为本地单调时钟。

业务要求：
1. 实现缓存节点声明、流水线清单与制品引用的本地 JSON 加载及强校验：从本地 JSON 读取节点集合（节点标识、回环端口、容量槽位、每节点租约上限、随机种子）与流水线清单（阶段、制品键、制品间引用、阶段并发配额），校验节点标识与制品键唯一、端口为回环字面量且全局不重复、容量槽位与租约上限为正整数、制品引用存在且引用图无环、阶段配额为正整数；任一不合法须以 E_SPEC 指明首个违规字段与期望约束。
2. 实现按制品键的确定性副本摘要与可复用性判定：每个缓存节点按自身随机种子与制品键以显式规则生成制品内容并计算内容摘要，相同节点与制品键多次生成的摘要必须逐位一致；以制品键、内容摘要与制品引用列表共同判定可复用性，须输出每个制品在每节点上的摘要、来源节点集合与可复用结论，结论不得依赖字典或哈希遍历顺序。
3. 实现回环 TCP 上的租约申请与逐行协议处理：以 Windows 子进程按节点声明启动缓存节点并绑定端口，流水线运行通过真实套接字发送包含制品键集合、期望租约毫秒与申请序号的请求行，接收含租约标识、内容摘要、容量占用与单调时钟毫秒耗时的回执行；握手须有真实套接字超时，端口占用、握手超时与回执字段缺失须分别以 E_PORT、E_HANDSHAKE、E_ACK 报告并写入结构化日志。
4. 实现同一制品键在多节点间的唯一服务节点仲裁与配额裁决：当多个节点均可服务同一制品键时，按内容摘要匹配优先、剩余容量槽位降序、节点标识序的稳定规则选定唯一服务节点，其他候选保留为对照并记录否决理由；节点租约数达到每节点上限或容量槽位不足时申请须排队，排队须记录入队时刻与稳定排队序号，不得绕过限制直接授予。
5. 实现租约到期回收与配额回收并存的唯一归属裁决：租约到期须以本地单调时钟真实计时判定而非人为延迟，到期时须同时释放节点容量槽位与租约计数；同一份容量权益在同一时刻不得既被计入到期回收又被计入配额回收，也不得被两个节点同时持有，须逐次输出归属变化的裁决依据与事件序号。
6. 实现受全局并发上限与每节点并发配额约束的并行租约处理调度：任一时刻在途租约请求总数与单节点在途请求数不得超限，配额耗尽时请求排队并记录等待开始与结束的单调时钟毫秒；调度须真实投射到工作线程池并向节点子进程发起真实套接字通信，不得以人为等待模拟超时或绕过配额。
7. 实现租约仲裁账本的持久化、版本识别整体替换与强制终止后的恢复：每次授予、续约、到期回收与配额回收须在同一 SQLite 事务中写入事件记录、节点容量余量、租约集合与进度游标，账本携带整数格式版本与内容摘要；进程被强制终止后重启只能依据已完整提交的记录恢复，处于未提交事务中的租约须标记为未知并要求重申请，不得承诺生成退出报告。
8. 实现独立重放校验工具与节点重启后的副本摘要收敛判定：验证工具仅读账本与原始声明文件，自行完成摘要生成、仲裁推导与归属裁决并与账本逐项比较，差异须以 E_VERIFY 定位到首个不一致的制品键、节点与字段；节点重启后须重新生成全部制品摘要并与账本留存摘要比对，摘要变化须使相关租约与复用结论整体失效并稳定列出受影响的制品键集合。
