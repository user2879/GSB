## 实测指标

### 跨格式指纹一致性

阈值 `0.55`。三首曲目的三组格式对均通过：

| 曲目 | 44.1k WAV vs 48k WAV | 44.1k WAV vs Vorbis | 48k WAV vs Vorbis |
| --- | ---: | ---: | ---: |
| Aurora | 0.835 | 0.743 | 0.741 |
| Cinder | 0.974 | 0.910 | 0.890 |
| Ember | 0.970 | 0.732 | 0.724 |

失配原因分类在全部通过对中为 `consistent`；负向探查用不同曲目配对触发 `E_FORMAT_DRIFT`。

### 检索与时间对齐

重复片段真值起点为 `1.45s` 或 `7.35s`：

- 44.1k/16-bit/mono 查询：Aurora 第一，分数 `0.369231`，对齐 `7.360726s`。
- 48k/24-bit/stereo 查询：Aurora 第一，排序与上者一致。
- Vorbis 查询：Aurora 第一，排序与上者一致。
- 对齐误差约 `0.0107s`，低于验收容差 `0.08s`。

移调 +3 半音素材由 `pitch-2bands` 假设找回；1.08x 变速素材由 `tempo1.08x` 假设找回，均排名第一。

### 去重

- 9 个格式来源归并为 3 个逻辑曲目。
- 每个逻辑组保留 3 个格式来源。
- 真值校验无误合并。
- 人为构造“同组不同真值”时返回 `E_DEDUP_MERGE`，带投票证据。

### 版本迁移

- `fp-v1` 索引打开为 `fp-v2` 后，迁移指纹行集合与全量 v2 重建逐行一致。
- 迁移后的逻辑内容哈希与全量 v2 重建相同；仅修订号不同（迁移自身增加一次修订）。
- 两种索引对相同查询返回相同的候选顺序、分数和对齐。
- 第二次打开迁移后索引不改变修订号与内容哈希，证明幂等。
- STFT 参数不兼容的副本返回 `E_INDEX_VERSION`，没有部分结果。

### 增量维护与恢复

- 向仅含 Aurora 的索引导入 Cinder 后，Aurora 查询投票数与对齐位置不变。
- 删除 Cinder 组后，该组剩余指纹行为 0，Aurora 查询投票数与对齐位置仍不变。
- 子进程在未提交事务中被 `os._exit(42)` 强制终止；重启后未提交行不可见，组/来源/指纹数量与内容哈希恢复到最后提交状态。
- 注入的 `.tmp-*` 孤儿与恢复后的 rollback journal 均被识别并回收。

### 可复现性

两次独立完整运行的文件树 SHA-256 比较结果：

- 文件数：27
- 差异文件：0
- `repeatability.ok = true`

输出覆盖合成 WAV/Ogg、manifest、多个 SQLite 索引、JSON 报告和 Markdown 报告。
