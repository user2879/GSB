# 技术说明

## 状态边界

系统把一份运行状态拆为五类阶段产物：`validation`、`domain`、`intent`、`slots`、`recalibration`。阶段产物不直接保存可变对象，而是保存内容寻址缓存条目：

```text
stage + utterance_content_fingerprint + stage_configuration_fingerprint -> product
```

每个条目还记录 `references` 和 `utterance_ids`。编辑命令只负责改变数据/配置并产生候选失效话语；真正是否重算由阶段键决定。因此“命令影响面”与“实际重算面”分离，避免粗粒度失效。

## 为什么下游键不直接包含整份配置

领域选择可能受所有领域触发词影响，所以 `domain` 键包含完整领域触发表；但 `intent` 键只包含已选领域的意图表和全局否定规则。这样修改账号领域触发词不会使账单话语的意图/槽位阶段失效。槽位键只包含已选意图的模式及槽位声明；再校准键只包含槽位摘要、基础分数和再校准配置。

无领域命中的话语仍输出意图阈值字段，因此空领域的 `intent` 键也包含意图阈值和量化参数，避免阈值修改后复用旧结果。

## 确定性来源

- 触发词匹配使用 UTF-8 字符索引；
- 所有比例使用 `Fraction`，不经过二进制浮点；
- 量化采用非负有理数半入舍入；
- 集合输出前显式排序；
- 并发任务只读输入，按提交顺序收集结果；
- 预算只在主线程按稳定队列扣减；
- 失败、边界、缓存账本均使用多级稳定排序；
- 摘要使用 `json.dumps(sort_keys=True, separators=...)` 后的 SHA-256。

## 恢复判定

快照中有三个不可混淆的量：

- `config_hash`：提交游标处的当前配置语义哈希；
- `command_stream_fingerprint`：提交时已应用命令前缀的指纹；
- `base_input_fingerprint`：基础话语、基础配置和词表路径的指纹。

续跑时先用清单中的游标截取当前命令流，再计算期望配置哈希。这样新增命令是合法前缀扩展，而改写历史命令或基础输入会判陈旧。

## 已知设计取舍

- `quantization_levels` 在规范配置中作为定点刻度分母解释，而不是“离散等级个数”。这能直接表达 5 位小数的 100000 刻度；如需离散等级，可在适配层换算为分母。
- 领域触发词修改会使领域阶段全局重算，因为所有领域候选共同参与领域选择；这是业务上必要的失效，不是缓存粒度不足。
- `cache.reuse_recompute` 的状态是运行相对量；跨增量/全量比较的稳定字段是业务结果内的 `stage_cache_keys`。验收按稳定业务字段比较，缓存状态用于证明本轮复用/重算行为。
