# 技术设计

## 1. 模块边界

| 模块 | 职责 |
| --- | --- |
| `config.py` | YAML 规范化、逐字段校验、配置指纹。 |
| `loader.py` | JSONL 逐行校验、类别域/数值有限性检查、分组映射规范化、分组覆盖检查。 |
| `injection.py` | 行级真实注入与配置影子注入，命中记录。 |
| `stats.py` | 列/分组证据、定点统计、统计缓存键和精确复用。 |
| `impute.py` | 稳定待办队列、预算切片、确定性噪声、单元格指纹。 |
| `model.py` | 固定划分和批量顺序的逻辑回归、损失轨迹、模型依赖指纹。 |
| `snapshot.py` | staging 全量写、不可变代、manifest 比较交换提交与完整性校验。 |
| `engine.py` | 编辑批次事务、阶段调度、报告、恢复和全量重建一致性。 |

## 2. 数据与事务流

```text
输入校验
  └─ 应用编辑批次（只改内存副本）
       └─ 统计量汇聚（按列/分组内容键复用）
            ├─ 提交 stats_ready 快照
            └─ 插补预算切片
                 ├─ pending：提交完整快照并保留队列
                 └─ done：模型训练/评估
                      ├─ 指纹不符：E_UPSTREAM_STALE，拒绝旧结果并重训
                      └─ 提交 completed 快照
```

编辑批次先应用到内存副本；在首次完整快照提交前被强制终止时，批次视为未发生，重启后会重新应用。提交后 `in_progress_batch.applied=true`，重启不会重复执行追加/修正操作。

恢复校验使用排除执行参数后的基础配置语义哈希。`thread_pool_workers`、`batch_cell_budget` 和 `snapshot_interval_batches` 可在恢复时直接更新并沿用持久化待办；列策略、模型超参、数据、映射或计划变化仍视为不兼容基础输入。

## 3. 指纹与失效

- 列统计键：`hash(阶段, 列名, 插补参数指纹, 内容证据指纹, 位宽, 量化档位)`。
- 分组统计键：参数、分组名、该组成员行及原始分组键值的内容证据。
- 单元格键：列参数、来源统计键/指纹、行标识、位宽、量化和舍入模式。
- 模型输入键：全部列/分组统计指纹、全部行的原始值/插补单元格指纹、行划分、模型超参。

| 变化 | 统计层 | 插补层 | 模型 |
| --- | --- | --- | --- |
| 修正某行某列非缺失值 | 该列；若键为分组列则受影响分组 | 引用该统计键的缺失单元格 | 依赖指纹变化则重训 |
| 把值改为缺失 | 该列/所属分组 | 新缺失单元格计算 | 重训 |
| 修改单列插补方式 | 仅该列/该列分组 | 仅该列单元格 | 重训 |
| 新增分组映射但无现存行使用 | 无统计重算 | 无 | 复用 |
| 映射改变导致成员迁移 | 旧组和新组 | 相关组中缺失单元格 | 重训 |
| 追加行 | 接收非缺失证据的列；必要时新组 | 新行缺失单元格 | 重训 |

复用判定只读取持久化内容证据和键，不会重新执行未失效统计或单元格生成。

## 4. 定点、量化与噪声

数值值先换算为 `units = round(raw * 10^places)`，随后：

```text
quantized_units = round_half_even(units / quantum) * quantum
```

`places` 是定点小数位宽，`quantum` 是整数档宽。记录 `value_fixed`、`value_text`、`value`、`decimal_places`、`quantization_level`、舍入模式和舍入方向。

均值加噪声使用独立随机流：

```text
u1, u2 = SHA256("noise-u1" + row_id + column), SHA256("noise-u2" + row_id + column)
z = sqrt(-2 ln u1) * cos(2 pi u2)
raw = mean + z * sample_std * noise_coefficient
```

不读取 `random` 全局状态。

## 5. 统计与兜底

- 中位数：非缺失数值的中位数。
- 众数：类别计数最大；并列时取类别字典序最小值。
- 均值加噪声：均值与样本标准差（分母 `n-1`）。
- 分组中位数：以映射后的组为单位，每组独立缓存；记录成员行集合和原始键值。
- 常量：不依赖数据证据，但报告仍记录当前非缺失样本数。

低于最小有效样本数时：统计项 `sufficient=false`，添加 `E_INSUFFICIENT_SAMPLES`，`fallback_used=true`，插补使用列配置的兜底常量。新分组即使所有目标单元格均缺失，也会以零有效样本显式出现并兜底。

## 6. 调度与预算

所有待插补任务稳定排序为 `(column, row_id)`。一次预算切片最多新计算 `batch_cell_budget` 个单元格；缓存命中不消耗预算。未选中任务按原顺序写入 `pending_jobs` 并提交。下一次恢复重新按同一稳定顺序构造任务，缓存前缀直接复用，因此待办严格接续。

编辑批次只有在所有切片完成且模型完成后才标记完成。预算耗尽时模型阶段不运行，持久化模型为 `null`，避免下游误用旧结果。

## 7. 并发一致性

- 统计按排序列名创建任务，线程池 future 按任务顺序收集。
- 插补按稳定任务顺序截取预算，future 按同一顺序收集。
- 浮点模型计算单线程、固定顺序执行，不受插补线程数影响。
- 失败清单、分组清单和报告字段统一排序后写出。

## 8. 快照与恢复

提交协议：

1. 在 `generations/.staging-<random>` 写全部阶段产物并 fsync。
2. 将 staging 整体改名到不可变代目录 `generations/vNNNNNNNN`。
3. 再读当前 manifest，确认版本仍等于预期父版本。
4. 原子替换 `manifest.json`；旧代至少保留三代。

读取时只相信 manifest 指向的完整代，并校验每个阶段文件的 SHA-256。强制终止可能留下 staging 或未指向的完整代，但不会暴露半写 manifest。

`snapshot_interval_batches` 控制正常批次完成快照的节奏。出现预算待办、停止请求、错误或最终批次时，提交立即执行，不被间隔延迟；尚未提交的已应用批次在重启后会从未提交前状态重新应用。

可处理停止信号（SIGINT/SIGTERM/Windows SIGBREAK）设置停止标志；引擎在安全的切片/阶段边界提交当前状态报告并以 0 退出。不可捕获的强制终止不承诺生成退出报告，只承诺重启读取最近一次完整提交。

## 9. 异常注入隔离

- 非有限原始值：真实进入行校验并产生 `E_DATA_ROW_INVALID`，该行不进入统计/训练。
- 未映射分组值：值在类别域内但不在映射表，产生 `E_GROUP_MAP_INVALID`，该行排除。
- 位宽/最小样本越界：在影子配置上运行正常配置校验并记录 `E_CONFIG_INVALID` 和命中编号；实际流水线继续使用合法基础配置，以验证故障隔离。

报告中的 `injection_hits` 记录注入编号、阶段、目标行列、期望/实际业务码与是否命中。
