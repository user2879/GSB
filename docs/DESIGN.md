# 设计说明：本地多服务限流熔断降级链路

## 1. 分层与确定性边界

系统分为两层，保证业务结论逐字节可复现、运行时能力真实可用：

- **策略层（纯函数、无副作用）**
  - `rlcb/breaker.py`：滑动窗口熔断状态机（closed/open/half_open），全部比率用万分比整数定点。
  - `rlcb/ratelimit.py`：按声明 `rps_limit` 与到达序号推导的确定性准入，0 表示全拒绝。
  - `rlcb/lease.py` 的 `arbitrate_ownership`：按事件序号规范排序后重放归属。
  - `rlcb/invalidate.py`、`rlcb/planner.py`：失效传播与全量/增量选择。
- **运行时层（真实时钟/线程/套接字）**
  - `rlcb/clock.py`：生产用 `time.monotonic_ns` 的真实单调毫秒钟；测试用可推进的假钟。
  - `rlcb/worker.py`：每个服务一个真实子进程，在 `127.0.0.1` 声明端口监听逐行 JSON。
  - `rlcb/transport.py`：主进程 TCP 客户端，真实连接/读取超时，映射 E_PORT/E_TIMEOUT/E_REPLY。
  - `rlcb/scheduler.py`：真实 `ThreadPoolExecutor`，三重配额闸门。

结论摘要只由声明、到达顺序和 NumPy 定点计算摘要决定；墙钟耗时 `elapsed_ms` 单独记录，
不进入规范摘要与内容摘要，因此重跑、重放与线程交错下结论保持逐字节一致。

## 2. 强校验与行号定位

`rlcb/linejson.py` 用两遍解析：`json.loads` 负责正确的值解析，另写一个只识别结构标点与
字符串跨度的轻量词法器，前序记录每个对象、键、值的 1-based 起始行。`rlcb/spec.py` 据此在
首个非法字段处抛出 `E_SPEC`，错误体带字段路径、行号与来源文件名。校验项覆盖：服务标识唯一、
端口为 `127.0.0.1` 字面量且全局不重复、非负整数限流/并发、阈值 0..10000 万分比、降级档位
属于 {0,1,2,3}、请求到达序号按服务单调不减。

## 3. 熔断与降级状态机

- closed：请求执行并计入当前窗口；运行中失败率一旦达到阈值（含阈值 0 的边界）立即跳闸，
  该请求返回降级结论，状态转 open，并记录触发窗口、失败计数与 `a>=b` 的阈值比较依据。
- open：触发窗口剩余请求及窗口结束前的请求全部降级、不执行；跨窗口边界转 half_open。
- half_open：新窗口作为恢复探测，探测窗闭合时失败率低于阈值计一次干净窗口，连续
  `recovery_windows` 个干净窗口后闭合；探测中再次达标立即重新 open。
窗口索引为 `arrival_seq // window_length`，与批次切分无关，因此任意批次切分、任意字典遍历
顺序下结论逐字节一致（见 `tests/test_breaker.py`）。

## 4. 租约与唯一归属裁决

租约含租约标识、服务、批次、授予/到期毫秒、版本号与配额版本。续约走乐观版本校验：
主进程凭版本号向服务子进程的权威版本表校验，版本不符抛 `E_LEASE` 且不延长到期时刻。
过期由真实单调钟判定（`now >= expires`），不使用人为 sleep。

到期回收（expired）与配额换代作废（superseded）并存时，同一槽位同一时刻只产生一条回收
事件：若已到期则 expired 优先，否则 superseded。所有变化写入带事件序号、版本与裁决依据的
事件流，`arbitrate_ownership` 对事件按 `event_seq` 重排后重放，任意物理遍历顺序都得到
相同归属，且同一槽位不可能被两个服务或两个批次同时持有。

## 5. 三重约束并行调度

每个执行批次在工作线程中依次获取：全局活跃租约 -> 全局批次预算 -> 每服务并发，固定获取顺序
避免死锁；越界即在条件变量上排队，记录单调毫秒的等待开始/结束。线程池真实投射，无旁路。
同一条 TCP 连接的请求/响应用锁串行化，避免多线程帧交错（不同服务仍各自独立套接字并行）。

## 6. 失效传播与增量重算

依赖链固定为：服务参数 -> 窗口 -> 租约 -> 批次 -> 请求。任一参数字段变化使该服务
`config_version` 单调 +1，参数摘要改变；仅该服务的窗口、租约、批次与请求进入失效集，
其它服务的结论摘要与租约归属从账本原样复用、逐字节不变。`planner.py` 以显式边界
（服务数 >4、批次数 >=6、窗口数 >=8、变更占比 <=1/2）选择默认路径并输出理由与边界值，
也可用 `--mode full|incremental` 强制。

## 7. 账本、快照与崩溃恢复

SQLite 账本将每批次结论、租约归属、失效轨迹与进度游标放在同一 `BEGIN IMMEDIATE` 事务，
携带整数 `LEDGER_FORMAT_VERSION=1` 与每条内容 SHA-256。重开时格式版本或整体摘要不一致即
整体替换（清空派生表）而非增量合并。强制终止后只信任完整提交批次：未提交批次标记 unknown
并先回收配额，再从干净基线重算补齐，最后逐请求重放并在首个差异处抛 `E_DIVERGENCE`。

## 8. 错误码对照

| 码 | 触发场景 | 模块 |
| --- | --- | --- |
| E_SPEC | 声明/请求非法，含首个字段与行号 | spec.py |
| E_LEASE | 乐观续约版本不符、过期续约、重复占用 | lease.py |
| E_PORT | 回环端口占用或子进程未监听即退出 | transport.py |
| E_TIMEOUT | 真实连接/握手/读取超时 | transport.py |
| E_REPLY | 回执缺字段、service_id 不符、非法 JSON | transport.py |
| E_LEDGER | 格式版本/应用标识不匹配 | ledger.py |
| E_DIVERGENCE | 重放逐请求比对出现首个差异 | ledger.py |
