# 技术设计

## 1. 模块边界

| 模块 | 职责 |
|---|---|
| `ossdiag/models.py` | JSON 声明加载与强校验 |
| `ossdiag/content.py` | 固定 64 KiB 块的确定性字节生成 |
| `ossdiag/digest.py` | 叶/批次/分片/对象摘要与三种聚合器 |
| `ossdiag/planner.py` | 整数工作量模型、路径选择、边界决胜 |
| `ossdiag/lease.py` | 租约签发、续约、过期、配额水位 |

## 2. 确定性内容和统一摘要

对象分片内容只由 `(object_key, shard_index, seed, shard内偏移)` 决定。每 64 KiB 内容块由 BLAKE2b 混合键、分片号、种子和块号，派生出本地 PCG64 流；因此批次边界、线程调度和聚合路径不会改变任何字节。

规范摘要层级：

1. **内容叶**：固定 64 KiB，叶摘要包含对象键、分片号、叶序号、叶长度和原始字节。
2. **分片根**：对叶摘要使用 RFC-6962 风格的规范 Merkle 树。流式栈、递归分层树和滑动窗口最终都产出同一根。
3. **对象根**：按分片号排序，将对象键、总字节数、分片字节区间和分片根写入 SHA-256。

批次摘要覆盖对象键、分片号、分片内偏移、批长度和真实批字节，仅用于批次完成/回读校验，不参与分片根定义。

## 3. 三路径与成本模型

三种聚合器共享叶摘要，但数据结构不同：

- `direct`：逐分片实时维护 Merkle 前沿，内存 `O(shards + log(leaves))`。
- `sliding`：使用 32 个叶摘要的有界窗口，顺序冲刷到规范前沿，内存 `O(window + log(leaves))`。
- `hierarchical`：保留全部叶摘要，最终物化分层树，内存 `O(leaves)`。

令 `L` 为内容叶数、`B` 为批次数、`S` 为分片数，整数工作量为：

```text
direct       = 2L + 10S + B^2/S + 16
sliding      = 2L + 4S + 2B + L/32 + 80
hierarchical = 1.5L + 4S + B + L/4 + 256
```

选择规则：

1. 按 `(score, path)` 确定最低分和次低分。
2. 若 `runner_up - best < tie_threshold_work`，标记边界情形。
3. 所有与最低分差距小于阈值的候选中，按稳定优先级 `sliding > hierarchical > direct` 决胜。
4. 结果、理由、所有候选分数和内存等级写入账本与仪表盘。

恢复时读取账本已记录的路径和缩放因子，不重新选择路径。

## 4. 调度与三重配额

调度器只为未完成分片创建工作项。主调度循环按 `(object_key, shard_index)` 稳定排序，并在提交到线程池前申请租约：

- 全局活跃租约数不超过 `global_lease_quota`。
- 每对象活跃租约数不超过 `min(concurrency_limit, lease_policy.max_concurrent_leases)`。
- 过期租约在每次 grant/renew/expire/snapshot 时按 `time.monotonic_ns()` 判定并立即扣减配额。
- 每个工作项记录排队开始、获准开始和预算等待起止单调毫秒。

吞吐预算为会话累计字节上限。每批在构造前原子预留预算；若剩余预算不足，记录等待后以 `E_BUDGET` 终止该批，不会构造超额字节。恢复运行会把账本已提交字节计入初始已用量，避免跨重启重复透支。

## 5. 批事务协议

每个批次严格按以下顺序执行：

1. `BEGIN` 写入 `inflight` 意图，提交。
2. 生成确定性字节，计算批次摘要与叶摘要。
3. 写入分片文件，`flush + fsync`。
4. 从同一文件句柄回读本批字节，重算批次摘要并比较。
5. 检查租约仍有效；若中间过期则撤销 inflight、截断本批、重新申请租约后重跑。
6. 最后一批额外读取完整分片文件，重建分片根并与内存聚合根比较。
7. 在同一个 SQLite 事务中写 `batch_commits`、`shard_leaves`，更新 `shards` 游标/摘要/版本/续约次数/完成时刻，删除 `inflight` 并刷新账本内容摘要。

因此崩溃只会留下两种状态：完整提交的批次，或仍带 `inflight` 意图的未提交批次。

## 6. 账本与整体替换

SQLite 表：

- `meta`：整数格式版本字符串、会话声明摘要、整体内容摘要、时间戳。
- `objects`：声明、选中路径、理由、候选分数、缩放因子、对象摘要。
- `shards`：区间、游标、完成状态、分片摘要、部分摘要链、租约版本、续约次数、耗时、未知标记。
- `batch_commits`：每批区间、摘要、租约版本、续约次数、完成时刻、游标。
- `shard_leaves`：固定叶序号和摘要。
- `inflight`：未提交批意图。
- `lease_runtime`：每次租约版本的运行状态。
- `snapshots` / `replacement_shards`：整体替换后的只读备份和稳定排序的旧分片集合。

账本内容摘要覆盖格式版本、会话声明摘要以及上述所有逻辑行的规范 JSON。每次写事务内刷新，磁盘分片另行全量复核：完整分片要求大小、叶摘要和根一致；未完成分片要求文件长度等于游标且已存叶摘要覆盖完整。

发现格式版本、声明摘要、账本摘要或磁盘数据任一不一致时：

1. 使用 SQLite online backup 复制旧账本。
2. 设置旧备份只读权限并记录快照。
3. 删除当前 SQLite/WAL/SHM，新建空账本。
4. 写入 `snapshots` 和稳定排序的 `replacement_shards`。
5. 返回 `E_SNAPSHOT`，随后按新账本重跑。

替换是整体重置，不做旧分片与新分片的增量合并。

## 7. 强杀恢复

重启顺序：

1. 校验账本格式版本、声明摘要和整体内容摘要。
2. 若 `inflight` 存在，只把其所属分片标为 `unknown`，删除未提交意图，截断文件到已提交游标。
3. 将所有仍为 `active` 的持久化租约改为 `reclaimed_after_crash`；新进程从空活跃租约集合开始。
4. 复核磁盘中已提交叶和完整分片摘要。
5. 读取账本记录的路径、缩放因子和已提交叶摘要，从游标继续。

系统不读取也不推测强杀时的内存状态，不生成“强杀退出报告”。恢复摘要只能来自完整提交的批次。测试将恢复后的分片摘要和对象摘要与干净一次执行逐项比较。

## 8. 定点统计与误差

缩放因子为 `S = 10^scale_exponent`。所有非负值向下取整：

```text
ratio_fixed(n, d) = floor(n * S / d)
duration_fixed(ns) = floor(ns * S / 1_000_000)   # 单位：定点毫秒
```

所有结果饱和到 `[0, 2^63 - 1]`。单值量化误差小于 `1/S`；两个比例差值的保守比较界为 `2/S`；对象级聚合同样声明 `2/S` 上界。

对象完成率按整数已提交字节/总字节计算。排序先按完成率降序划分误差簇：相邻差小于 `2/S` 的对象进入同一簇；簇内按对象键字典序排序，并标记 `ordering_affected_by_error_bound=true`。受影响的比较对同时列出实际定点差和误差界。

## 9. 异常注入

- `--inject-lease-overflow`：真实填满某对象的租约额度，再申请一个分片，产生业务 `E_LEASE`；探针租约随后释放。
- `--inject-digest-mismatch`：在真实批字节回读后仅替换观测摘要，产生 `E_DIGEST`；错误摘要不提交。
- `--inject-snapshot-conflict`：以运行参数强制进入整体替换路径，产生 `E_SNAPSHOT`，备份并重建账本。

三者都会写 JSONL，含 `monotonic_ms`、`code`、`object_key` 和 `shard_index`。源码没有通过开关改变摘要算法或伪造账本内容的条件分支。

若摘要注入目标所在会话已经全部完成，则改用只读“完成态摘要探针”：从落盘叶重算真实摘要，再将观测值替换为注入值并报告 `E_DIGEST`；账本与分片文件保持不变。

## 10. Tkinter 界面

对象表显示状态、路径、边界标记、完成率、平均分片摘要耗时、续约率、对象/全局租约水位、摘要结论、未知分片数和对象级误差界。分片表显示范围、状态、游标、摘要、租约版本、续约次数、完成时刻和未知标记。快照页显示备份路径和替换分片数量；“路径与事件”页显示成本估计、决胜理由、误差敏感排序和快照替换集合。

`build_dashboard()` 只执行 SELECT 和内存快照，不使用会触发过期回收的租约快照；自动化测试比较刷新前后的账本摘要和分片行。
