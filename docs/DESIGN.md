# 定点解码采样链 — 技术设计

## 1. 目标与边界

组件在定点整数域内完成 LLM 逐请求解码采样链：温度缩放、TopK 与核采样截断、
确定性抽样、逐请求结论与可复核账本。所有输入、样本、配置与账本均在本地文件系统，
服务仅概念性运行于回环环境，不依赖容器、GPU、网络服务或外部数据集。

## 3. 定点数字内核

1. `scaled = logprob / temperature`，温度为正有限数。
2. 稳定 softmax：先减最大值再指数化归一，避免上溢。
3. 量化到尺度 `S = 10**width`：
   - `ROUND_HALF_UP`：`floor(p*S + 0.5)`；`FLOOR`：`floor(p*S)`。
   - 残差修正：按小数余数确定性排序，补齐/扣减使整数和恰为 `S`。
   - 每个令牌记录量化步长 `S`、原始整数、残差与最终整数。
4. 参考路径以 `width+1` 位宽、半上取整生成，作为误差归因基准。
5. 切换温度、位宽或档位会真实改变中间整数；同一输入的随机源仅由指纹派生，
   不读取 `random` / `numpy.random` 全局状态。

## 4. 截断与边界诊断

- 排序：定点概率降序，同值按令牌标识升序，保证并列确定性。
- TopK 截断后，按 `top_p_mille * S / 1000` 的整数阈限累加最小前缀。
- 跨越阈限时按量化半步（`S/20`）决断：越限不超过半步则纳入并标记
  `HALF_STEP_INCLUDE`，否则标记 `OVERSHOOT`；恰等为 `EXACT`。
- 边界令牌同时输出高一位宽参考（缩放回当前位宽）与两个差值：
  - `rounding_diff`：温度缩放舍入来源；
  - `accum_diff`：截断累加顺序来源；并据此归类 `TEMP_ROUNDING/ACCUM_ORDER/BOTH`。

## 5. 确定性抽样与增量复用

- 随机种子由 `sha256(请求步级指纹 | 序列 | 步序号 | 配置指纹)` 派生，
  随机数为 SHA-256 计数器模式，拒绝采样消除取模偏差。
- 在截断后的整数分布上以 `target = floor(unit * kept_total)` 落入累计区间，
  记录被选令牌、抽样依据、每个令牌的 `[lo, hi)` 区间与并列令牌。
- 缓存键细化到“序列+步”指纹：替换单步只失效该步，追加只新增，
  未受影响步直接命中复用；配置变更重写配置指纹段，未受影响材料仍可命中。

## 6. 双版本交换

- v1：固定字段宽度的 ASCII 行（请求序号、序列、步、千分比整数概率、整数令牌码、
  覆盖标记），宽度不足或非法字符返回确定业务码，绝不猜测补齐。
- v2：JSON，携带浮点概率、命名令牌与命名量化方案。
- 量化残差、高一位宽参考、精度标签与被覆盖引用写入旁路元数据；
  v1 通过独立 sidecar JSON、v2 通过内嵌 sidecar 还原，往返后内部表示逐字段等价。

## 7. 调度三重约束与恢复

- 任务携带 `request|seq|step` 稳定排序键，按稳定顺序消耗预算。
- 批预算或单请求配额耗尽只中止当前批次，任务进入待办，下一批优先处理且配额重置。
- 单步重算上限命中时该任务永久保留待办并记业务码；仅当连续两轮零完成且待办集合
  不变才停止，避免活锁。
- 快照先写临时文件再 `os.replace` 原子整体替换；恢复只读取完整快照，
  并比对版本号与配置哈希，不匹配返回 `STALE_SNAPSHOT_VERSION`/`CONFIG_HASH_MISMATCH`。

## 8. 误差归因与故障注入

归因对每个请求步输出四环节差值并给出首次超容差环节：
温度缩放、截断累加、抽样决策、版本转换。故障注入通过独立配置施加
非有限概率、越界阈限、步序号回退，命中记录 `injection_id`；
单请求失败被隔离，其余请求照常产出。

## 9. 业务码

见 `src/decchain/errors.py` 的 `BizCode`：1xxx 加载校验、2xxx 交换格式、
3xxx 调度预算、4xxx 容差、5xxx 注入标记。所有失败均带结构化 `location`，
逐条列出且不中途静默跳过。
