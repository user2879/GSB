# 设计说明

## 1. 模块边界

- `manifest.py`：严格解析与规范化清单；解析修订增量、派生规则和有效配置值。
- `planner.py`：生成稳定分片 ID、稳定序列化计划、每分片编译摘要与字段级比较。
- `evolution.py`：逐修订比较、依赖闭包、任务/集群引用传播、选择性计划与视图差异。
- `mock_service.py`：回环 TCP JSONL 服务；NumPy 分组聚合；父进程看门狗。
- `simulator.py`：子进程编排、真实超时握手、回执强校验。
- `scheduler.py`：预算预占式线程池调度与单调时钟轨迹。
- `store.py`：SQLite 账本、inflight、快照、当前视图、失效轨迹和预算统计。
- `session.py`：会话编排、世代替换、恢复、重放和一致性自检。
- `cli.py` / `ui.py`：命令行与可选只读界面。

## 2. 配置有效值

修订按版本升序装载。`values` 是相对父修订的增量，父修订的有效直接值作为基础；`derived` 规则同样继承。装载时递归解析派生键，检测未知输入和派生环，最终得到该修订的 `effective_values`。任务只能引用当前最新修订中存在的键。

## 3. 计划与摘要

逻辑分片 ID 为 `percent_encode(cluster_id)::percent_encode(task_id)::sNNNNNN`，不包含修订号。修订号是独立字段，因此逻辑分片可跨修订对比。每分片编译载荷包含：

- 集群标识、固定种子、集群定义摘要；
- 任务与分片序号；
- 来源修订版本；
- 引用键、整数有效值、依赖闭包；
- 资源单位、任务并发；
- 固定样本数与分组数。

计划先排序再序列化；分片编译摘要只覆盖该分片载荷。整个计划摘要覆盖规范化清单摘要和全部编译载荷。

## 4. 调度状态

每个分片经历 `pending -> running -> success|failed`。调度主线程在提交前同时检查并预占：

```
resource_in_use + shard.units <= global_budget
cluster_running[cluster] + 1 <= cluster.quota
task_running[task] + 1 <= task.limit
```

只有预占成功才调用 `ThreadPoolExecutor.submit`。`queued_at_ms`、`wait_start_ms`、`wait_end_ms`、`execution_*` 均为单调时钟毫秒。聚合服务耗时单独由服务端单调时钟返回。

## 5. SQLite 表

主要表：

- `ledger_entries`：不可变提交行，含结局、资源、摘要、修订、编译摘要、游标、行摘要、提交时间。
- `inflight`：按世代/分片记录 running、committed、unknown。
- `snapshots`：每次世代快照；`is_current`/`is_stale` 保证唯一当前结果，内容摘要覆盖完整 payload。
- `view_shards`：当前分片轨迹，含编译摘要、状态、聚合摘要和账本行号。
- `invalidations`：当前失效轨迹及传播依据。
- `generation_stats`：当前预算/并发统计。
- `meta`：数据库结构版本、整数账本格式版本、全局游标、账本内容摘要、世代序号。

每次分片提交在 `BEGIN IMMEDIATE` 中完成账本插入、inflight 更新、游标更新和全账本内容摘要更新。进程在任意点死亡时，SQLite 只保留完整事务。

## 6. 世代整体替换

开始运行前先写 `phase=prepared` 快照，同时把旧快照、旧视图、旧失效轨迹和旧统计设为 stale。执行完成后用同一世代 ID 原子替换为 `phase=complete` 快照。若中途崩溃，当前库里仍只有 prepared 快照，不会伪装成退出报告。恢复时依据账本完整行和 prepared 计划重建。

任何版本或摘要校验失败都会立即走整代重建：不会将旧视图行叠加到新视图。重建后的计划仍会读取当前清单和已提交账本，但当前结论只来自新快照。

## 7. 失效传播

比较窗口包括旧最新修订到新链中每个后续修订之间的变化，以及最终有效值差异。对每个变化键：

1. 计算每个任务引用键在对应修订中的依赖闭包；
2. 若变化键位于闭包内，生成 `配置键 -> 派生路径 -> 任务 -> 目标集群` 依据；
3. 任务新增/删除/目标变化/分片参数变化、集群定义变化也分别形成直接依据；
4. 新逻辑分片使用最新修订重新编译；未失效分片传入旧来源修订进行选择性编译，并逐片断言编译摘要未变。

失效与删除分开报告；仅新计划中仍存在的失效分片进入重算集合。

## 8. 恢复与重放

重启过程：

1. 打开数据库时校验 SQLite 结构版本、整数账本格式和账本内容摘要。
2. 将所有 running inflight 改为 unknown，并把它们从可复用账本集合排除。
3. 仅复用结局为 success、修订和编译摘要都匹配的最近账本行。
4. 对复用行按稳定顺序调用相同集群模拟服务重算；按嵌套字段比较账本聚合摘要，首个差异抛 `E_REPLAY`。
5. 对 unknown/无账本分片重新编译执行；每片仍先标记 running，再在完成事务中提交。
6. 重建完整 current view、差异、统计和快照摘要。

## 9. 确定性

- 样本种子来自清单固定整数与稳定 SHA-256 派生值，不使用 Python `hash()`。
- 聚合使用 NumPy，分组按整数升序输出，浮点均值统一保留 6 位。
- 计划、摘要和 JSON 快照均使用 `sort_keys=True`、紧凑分隔符和 UTF-8。
- 时间字段只用于观测，不参与聚合摘要或分片编译摘要。
