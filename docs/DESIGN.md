# 设计说明

## 1. 模块边界

| 模块 | 职责 |
| --- | --- |
| `config.py` | 配置解析、候选位宽规范化、训练影响项哈希 |
| `data.py` | JSONL 分片校验与数据哈希 |
| `model.py` | 参数初始化、确定性伪梯度、窗口梯度累加、非有限值扫描 |
| `quantization.py` | 定点量化、位打包、二进制定点包头、解压头校验 |
| `topology.py` | 环形/全连接链路和链路预算 |
| `decision.py` | 候选位宽评分、预算约束、聚合顺序、收发计划 |
| `comm.py` | 每工作号 TCP 接收器、回环发送、预算账本 |
| `error_tracking.py` | 三阶段误差、容差判断、低一位宽边界判定 |
| `retention.py` | 保真梯度窗口轮转 |
| `snapshot.py` | 临时目录、提交目录、根清单原子替换、磁盘校验 |
| `engine.py` | 阶段状态机、线程池、异常隔离、恢复与报告 |
| `verify.py` | 快照、预算、记录对应关系和保真引用验证 |

## 2. 确定性伪梯度

模型先生成一次基准参数，再为每个工作号复制独立参数副本。张量形状由 `hidden_dim` 占位符和显式维度共同解析，完整张量名为 `layer_<n>.<name>`。

每个伪梯度元素由 SHA-256 派生种子生成，材料包含：

```text
config.seed, step, worker_id, tensor_index, tensor_name,
worker shard context (shard_id, samples, feature_digest, label_digest),
single shard id, feature_digest, label_digest
```

多分片按样本数加权累加。窗口包含多个训练步时，先逐步派生 `float32` 梯度，再以 `float64` 累加并转换回 `float32`。所有随机源使用显式 `PCG64`/`SeedSequence`，不依赖全局随机状态或线程顺序。

参数更新规则：

```text
new_param = round_fixed_point(old_param + aggregated_gradient, selected_quantum)
```

其中 `round_fixed_point(x, q) = rint(x / q) * q`。非有限梯度在派生阶段被记录并替换为有限值，非有限参数在扫描阶段被记录并清理，报告保留工作号和张量名。

## 3. 定点压缩包格式

包布局为固定宽度二进制头加位打包负载：

```text
magic "DPQ1" | version | scheme | bits | rank | zero_point | scale(float64)
| numel | payload_bytes | name_len | shape dimensions | tensor name
| header_crc32 | packed payload | payload_crc32
```

数值字段均使用固定宽度大端编码，因此相同张量、形状和位宽下，包长度不受梯度和缩放因子数值影响。负载长度为 `ceil(numel * bits / 8)`，元素按 LSB-first 位平面打包。

解压前依次校验：

- 魔数、版本、方案代码、位宽和秩；
- 缩放因子有限且为正，零点在可表示范围内；
- 形状维度与 `numel` 一致；
- 负载字节数严格等于由形状和位宽推导出的长度；
- 头部 CRC、负载 CRC、期望张量名/形状/位宽/方案。

对称方案使用 `[-qmax, qmax]`，非对称方案使用 `[0, 2^bits-1]` 与零点偏移。一个窗口内同一张量跨工作号共享缩放因子和零点，使接收端可在整数域聚合。

## 4. 预算决策与聚合顺序

候选集合来自配置中的方案与位宽笛卡尔展开。对每个候选：

1. 用全部工作号当前梯度计算共享定点参数；
2. 计算压缩包长度、每个链路窗口字节数和窗口总字节数；
3. 计算定点量化/聚合最大绝对误差与最大相对误差；
4. 判断链路预算、窗口预算和绝对误差容差；
5. 记录包字节、误差、容差标记、评分、预算标记和每张量误差。

评分综合误差比例和字节比例；满足预算且满足容差的候选优先，其次选择较低评分。没有候选满足预算时，优先选择压缩后总字节数最小的候选，并在实际发送时由预算账本输出 `E_COMM_BUDGET_EXHAUSTED`。

聚合顺序支持：

- `name_asc`：张量名字典序；
- `bytes_desc`：压缩字节数降序，字节数相同按张量名字典序；
- `auto`：最大包与最小包达到 1.5 倍差异时使用 `bytes_desc`，否则 `name_asc`。

每个发送任务记录由窗口号、来源工作号、张量名、路由轮次和目标工作号组成的稳定键。记录在报告中按稳定键排序，同时保留线程池提交时的 `execution_sequence`。

## 5. 回环通信

每个逻辑工作号创建一个绑定 `127.0.0.1:0` 的 TCP 接收器，操作系统分配端口。发送帧固定包含来源、当前持有者、目标、路由轮次、窗口号和压缩包长度，随后是压缩定点包。

全连接拓扑直接向每个目标发送一次。环形拓扑执行单向环 allgather：第 `r` 轮由当前持有者把来源包发给后继工作号，经过 `W-1` 轮后每个工作号拥有全部来源包。转发内容取自前一轮通过套接字收到的压缩包字节，不使用进程内梯度共享替代通信。

接收器验证帧和压缩包头，再按 `(窗口号, 来源工作号, 张量名)` 存放。发送线程只负责压缩包传输，聚合阶段重新解析接收包得到整数数组。原梯度数组仅用于 `float64` 真值参照。

预算账本以实际线路字节数（固定帧头加压缩包）原子预留链路和窗口额度。发送失败时释放预留；预算拒绝时记录链路当前已发送字节、请求字节和预算。

## 6. 并发与确定性

收发计划在进入线程池前完成确定性排序。环形拓扑按路由轮次分批以保证转发依赖，每批内部按来源工作号和张量顺序排序；全连接拓扑按来源、张量顺序和目标排序。

并发度取以下最小值：

```text
配置并发数、预算可容纳至少一个帧的链路数、
链路总容量可容纳的帧数、窗口预算可容纳的帧数
```

最终发送记录、误差归因、边界张量和失败记录均独立排序。聚合时按来源工作号排序后累加，因此线程调度不会改变浮点累加顺序或输出顺序。

单体发送异常转为失败记录后继续其他任务。环形转发缺少上游包时记录 `E_COMM_PACKET_UNAVAILABLE`；已发送但目标未收到的帧记录 `E_COMM_RECEIVE_MISSING`。接收缺失是业务失败，不会被描述为强制终止或线程失控。

## 7. 误差追踪

对每个窗口、目标工作号和张量：

- **真值**：全部来源原始梯度按来源号排序后用 `float64` 聚合；
- **打包阶段**：来源端整数反量化后按 `float64` 聚合，与真值比较；
- **解压阶段**：目标端收到的整数反量化后按 `float64` 聚合，与真值比较；
- **定点聚合阶段**：所有来源整数相加，按 `mean`/`sum` 规则定点舍入后再反量化。

每个阶段记录最大绝对误差、最大相对误差和是否超过容差。容差判定使用最大绝对误差；相对误差保留用于诊断。首个超限阶段依次按 `pack`、`unpack`、`aggregate` 标注。

边界检测选择同方案下比当前位宽低的最高候选位宽，重新量化并计算三阶段判断。若当前位宽与低位宽的容差判定不同，记录边界张量、两侧阶段指标、首次超限阶段，以及 `quantization` 或 `fixed_point_aggregation` 误差来源。

## 8. 快照与恢复

每个阶段结束时写入完整状态：

- 参数、窗口梯度、已压缩包；
- 决策、候选评分、发送记录和预算账本；
- 接收整数、定点聚合结果；
- 误差归因、边界、失败、保真轮转和窗口记录。

写入流程：

1. 在快照根目录创建唯一 `.staging-*` 目录；
2. 写入数组、压缩包、`state.json` 和内部 `manifest.json`；
3. 计算所有文件 SHA-256；
4. 将临时目录整体重命名到 `commits/v<version>-<uuid>/`；
5. 通过临时文件加 `os.replace` 原子替换根 `manifest.json`。

根清单是提交点。阶段在目录重命名后、根清单替换前被强制终止时，旧清单仍指向旧完整提交。恢复优先使用根清单；只有根清单缺失或损坏时才扫描最新完整提交。

清单记录阶段名、配置哈希、拓扑哈希、数据哈希、版本号、窗口边界、已完成步游标、快照间隔和保真代数。未完成阶段的游标停在窗口起点；`tracked` 提交后游标推进到窗口终点。`communicated` 提交恢复时直接进入追踪阶段，不重新打开套接字。

## 9. 保真轮转

每个窗口将 `float64` 真值聚合梯度转为 `float32` 保真副本。保留数量超过 `fidelity_generations` 时，按窗口号递增顺序移除最旧条目。替换事件记录新窗口、被替换 ID、被替换窗口、新 ID 和原因。

保真副本只用于诊断和快照重建，不参与当前窗口的量化、发送或聚合。当前快照保留条目写入独立数组目录，并可被报告中的保真 ID 引用；已轮转 ID 只保留在历史事件中。
