# 设计说明：持久化、恢复与可验证结论

## 权威状态

SQLite 中 `events`、`messages` 与 `visibility` 构成权威状态；`transactions.current_state`、`partition_prefix` 和 `recovery_marks` 都是可重建的物化/诊断数据。恢复只从已提交事务中的记录重建结论。

关键表：

- `events`：连续 `event_seq`、事务、状态、本地事务版本、分区，以及规范 JSON 体、字节长度和体摘要。
- `visibility`：事务、分区、位点、消息摘要、生效事件序号，以及规范 JSON 体、字节长度和体摘要。
- `messages`：消息载荷、长度和消息摘要；分区位点有唯一约束。
- `partition_prefix`：前缀缓存，带 `computed_event_seq`，不是权威状态。
- `recovery_marks`：重启时发现的未知事务、位点区间和重跑要求。
- `meta`：整数账本格式版本、分区集合版本、事务集合版本和账本内容摘要。

## 原子写入窗口

一次状态推进分为两个数据库事务：

1. 原子事务 A：追加状态事件；若状态为 `committed`，同时追加该事务全部可见性记录；更新事务物化状态；逐条复核新记录长度与摘要；更新账本内容摘要。
2. 原子事务 B：从事件和消息重新计算全部前缀，并刷新前缀缓存。

进程可在 A 已提交、B 未执行时被杀。此时事件和可见性完整，旧前缀缓存可能陈旧。下次打开账本先验证 A 中记录，再从事件流重建前缀；缓存陈旧只会触发修复，不会污染恢复结论。

若进程在 A 内被杀，SQLite 回滚整个事务，事件和可见性不会只写一半。

## 连续可消费前缀

位点起点固定为 `0`，范围为 `0..max_position`，前缀是包含式最大位点：

- 若当前期望位点缺失，截断原因为 `missing`。
- 遇到 `aborted` 事务，截断原因为 `aborted`。
- 遇到 `prepared`，截断原因为 `prepared`。
- 遇到最新状态为 `committing` 的事务，截断原因为 `unknown`，同时把该事务全部消息位点合并成悬置区间。
- 事务全部 `committed` 时才继续向后推进。

`PrefixReport` 只包含确定字段，输出 JSON 使用排序键，因而批处理边界和事件读取顺序不会改变字节结论。

## 摘要边界

- 消息摘要：`sha256(canonical({"partition_id","position","payload"}))`。
- 记录摘要：对规范 JSON 字节求 SHA-256；长度按 UTF-8 字节数计算。
- 事务规格摘要：对不含 `spec_digest` 自身的规范事务规格求 SHA-256。
- 账本内容摘要：对格式版本、集合版本、分区、事务规格、事件和可见性的规范化整体求 SHA-256。
- 快照内容摘要：对快照除 `content_digest` 外的整体求 SHA-256；快照另存生成时的账本内容摘要并在恢复前重新计算校验。

记录损坏优先报 `E_REC`；当所有记录都自洽但整体内容摘要不符合 `meta.ledger_digest` 时，报 `E_SNAPSHOT`。

## 快照整体替换

恢复顺序：

1. 验证快照 `content_digest`、格式版本、事件连续性、事件流可重放、事务物化状态、前缀和未知标注。
2. 重新计算快照内嵌账本摘要，必须等于快照声明的 `ledger_digest`。
3. 用 SQLite backup API 将当前账本复制到 `backups/`，并设置只读权限。
4. 在同一 SQLite 事务中删除状态表并按快照重建；不做按事务或按事件的增量合并。
5. 重新校验账本摘要，重建前缀缓存和未知事务标记。
6. 写入恢复差异清单，列出新增、删除、版本变化和事务最终状态变化。

快照文件损坏不可信，以 `E_SNAPSHOT` 拒绝；快照自身有效但与当前磁盘版本/摘要不同，说明状态分叉，执行整体替换。

## 重放校验

重放器按 `event_seq` 排序输入，因此调用方输入顺序不影响结论。它独立执行状态机、生成可见性、推导前缀和未知事务，再与账本物化状态及可选快照基线逐项比较。比较顺序固定，首个差异立即转成 `E_REPLAY`，携带事件序号、事务与字段。最新状态为 `committing` 的事务进入未知清单，不参与最终状态差异失败。

## 日志与注入

所有业务错误使用唯一 JSONL 追加函数，保证包含时间、业务码、事件序号、分区和事务字段。异常注入不修改源码：损坏批次写入独立 JSON，重复位点写入独立批次，账本摘要异常来自当前账本的一致性副本，快照摘要异常来自快照副本。
