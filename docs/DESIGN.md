# 算法与可复现设计

## 1. 地形数据源

`TerrainConfig` 只接受边长 `257` 或 `1025`，默认种子为 `0x5EED1234`。高程生成完全使用整数和固定顺序的 NumPy 运算：

1. 用 SplitMix64 在 5 个固定格点层上生成种子相关的 `uint32` 值；
2. 以 16 位定点双线性插值采样到目标分辨率；
3. 叠加每层固定整数细节扰动，裁剪到 `[0,65535]`；
4. 以 C 顺序写出小端 `uint16` 原始文件。

不使用 `np.random`、浮点三角函数或平台随机源。地形元数据记录形状、字节序、最小值、最大值、每个噪声层的格点尺寸/权重/哈希和整幅内容 SHA-256。

## 2. 四叉树分块

叶块固定为 32 个地形段，即 `33x33` 个重叠采样点。257 地形深度为 3、共 64 个叶块；1025 地形深度为 5、共 1024 个叶块。每个节点记录：

- 层级、网格坐标、父节点和四个子节点；
- 含端点的样本范围 `[x0,x1,z0,z1]`；
- `uint16` 高程最小值/最大值/极差及世界坐标包围盒；
- 叶块原始字节数、内存驻留字节、显存驻留字节；
- 叶块高程 payload SHA-256。

清单按节点 ID 排序后使用规范 JSON 写出，清单自身计算内容哈希。

## 3. 相机与投影

- 世界坐标、视矩阵、投影矩阵：`float64`；
- 深度缓冲与 Hi-Z：`float32`；
- 高程：`uint16`；
- 变换固定为 `clip = P @ V @ [x,y,z,1]`，矩阵按行优先存储，列向量约定。

相机轨迹由归一化时间、固定正弦相位和地形双线性高度采样生成。每帧报告保存视点、目标点、近远平面、视矩阵、投影矩阵、视投影矩阵和数值策略。

对每个块计算保守屏幕包围盒和投影误差分量：

```text
float_roundoff_px = 16 * eps(float64) * max_abs_world_coordinate
pixel_snap_px = 1
subpixel_footprint_px = 1 / max(0.25, min(screen_width, screen_height))
perspective_depth_sensitivity_px = f * near * depth_span / (distance^2 + near^2)
near_clip_px = 2 当包围盒跨越近平面
```

总投影误差超过声明预算时，按固定优先级降低 Hi-Z 精度并增加屏幕保守外扩；触发块完整写入当帧报告。

## 4. 低分辨率深度与块归属

每帧使用固定 `64x64` 基分辨率。对所有视锥相交叶块：

1. 投影该块全部 `33x33` 高程样本；
2. 把落在 `[0,1]` 深度和视口内的样本写入最近深度；
3. 对每个样本做固定 `3x3` 像素溅射，写入深度增加固定安全偏置；
4. 深度相同时用较小块序号作为归属，得到 `owner` 图。

`owner` 图是可见性保守证据：若候选块在某像素是最前表面，它就拥有该像素，后续绝不允许被遮挡剔除。该机制避免“深度图包含候选自身导致自遮挡误剔除”，同时允许完全被近处地形覆盖的块被 Hi-Z 剔除。

## 5. Hi-Z

从 `64x64 float32` 深度开始，每级固定对 `2x2` 子区域取最大深度，直至 `1x1`。第 `L` 级误差上界：

```text
base_quant = 2^-24
level_error(L) = base_quant
               + (L + 1) * eps(float32) * max_abs_depth
               + (2^L - 1) * base_quant
```

每级保存宽度、高度、深度 SHA-256 与误差上界；整个金字塔保存层级元数据哈希、原始字节和总内容哈希。同一深度输入重复构建得到相同级别、字节与哈希。

## 6. 遮挡剔除判定

对每个叶块：

1. 用外扩后的世界包围盒做视锥判定；
2. 计算屏幕包围盒，按包围盒尺寸选择 Hi-Z 层级，再叠加降级偏置；
3. 在该层包围盒区域取最大深度 `z_hiz`；
4. 计算候选最近深度 `z_near` 和误差分量：

```text
projection_float = (float_roundoff_px + subpixel_footprint_px) * depth_per_pixel
bbox_expand      = extra_screen_expand_px * depth_per_pixel
                 + (base_world_expand + extra_world_expand) / distance
hiz_sampling     = level_error(L)
depth_bias       = declared_depth_bias
total_error      = sum(above)
delta            = z_near - z_hiz
```

5. 若候选块在 `owner` 图中有前表面像素，状态为 `VISIBLE`；
6. 空投影或投影面积小于 4 像素时直接保守保留；
7. 若 `delta > total_error`，状态为 `OCCLUDED`；
8. 若 `delta < -total_error`，状态为 `VISIBLE`；
9. 其余状态为 `UNCERTAIN`，与 `VISIBLE` 一起进入流式调度和绘制集合。

跨越近平面的包围盒使用整屏保守覆盖，因为其未裁剪前角点投影不能保证包住裁剪后可见区域。

每个决策记录块 ID、状态、原因、外扩参数、投影误差、Hi-Z 层级、查找区域、深度差、各误差分量和参数版本戳。

## 7. 流式驻留

调度顺序：

1. 保护当前帧所有可见/不确定块；
2. 为必须加载的可见块预留预算，只淘汰非保护块；
3. 完成全部可见块加载；
4. 更新可见块 LRU 时间并记 `RETAIN`；
5. 在剩余预算内按相机距离顺序投机预取相邻块；
6. 对所有加载完成后仍不在期望集合中的非可见块执行卸载；
7. 再次审计可见块是否全部驻留、内存/显存是否低于预算、账本状态是否一致。

若可见工作集本身超过内存或显存预算，返回 `E_BUDGET_DENIED`，不会产生“先卸载后加载造成漏块”的状态。重新加载同一块会校验清单中的 payload SHA-256；绘制摘要只由可见块 ID 与其内容哈希决定，因此卸载再加载的摘要必然与持续驻留时一致。

## 8. 固定优先级降级

1. `LOWER_HIZ`：增大 Hi-Z 层级索引，使用更粗、更保守的最大深度区域；
2. `EXPAND_BBOX`：增加屏幕像素和/或世界空间外扩；
3. `REDUCE_RESIDENT`：跳过部分投机预取，减少非必需驻留。

前两项由投影误差预算或深度误差预算触发；第三项由内存/显存预算压力触发。决策序列、触发块列表、预算快照和参数版本戳都会写入逐帧报告。

## 9. 确定性控制

- 地形格点哈希和噪声都是整数运算；
- 分块、决策、驻留和取消驻留都按块 ID 排序；
- 浮点写入规范 JSON 前统一量化到 12 位十进制；
- 输出不包含绝对工作区路径、随机数、时间戳或墙钟耗时；
- 运行清单逐文件记录相对路径、字节数和 SHA-256，并计算整树哈希；
- 双跑比较同时做逐文件字节比较和逐帧逐块状态比较。

## 10. 业务错误码

`E_HEIGHT_RANGE`、`E_BLOCK_MISSING`、`E_HIZ_LEVEL`、`E_DEPTH_BIAS`、`E_BUDGET_DENIED`、`E_RESIDENT_LEAK`、`E_TRACK_DIVERGE` 均由 `WorkbenchError` 携带机器可读上下文。`demo` 会逐项注入并验证实际返回码。
