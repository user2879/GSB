# 隧道重组窗口裁决组件 — 技术说明

## 1. 领域问题与建模边界

组件不做“按隧道/窗口配额转发”或“按分片偏移简单重组”，而是回答一个可复核的
判定问题：**接收端与发送端存在相对时钟偏差时，某个组在偏差估计的哪个版本下
落入哪个重组窗口，该判定如何随估计版本翻转，并如何固化进账本。**

时间轴约定（全部整数毫秒）：

- `send_ms`：应用侧标注的发送时刻，来自发送端时钟。
- `arrive_ms`：接收端用本地单调时钟（`time.monotonic_ns()` 截整到毫秒）记录的
  到达时刻，是后续一切判定唯一可复核的时间来源。
- 偏差样本（每组一个）：`skew_sample = arrive_ms - send_ms`。
- 折算公式：`adjusted_ms = send_ms + skew_estimate`，把发送端时刻折算到本地基准。

## 2. 偏差估计（业务要求 3）

- 中位数规则显式化为**下中位数**：排序后取索引 `(n-1)//2`，偶数样本偏低位一侧，
  全程无浮点，跨进程/跨回放逐位一致。
- 样本数低于通道声明的 `min_estimate_samples` 时，估计标记为未定（版本 0、
  `skew_ms=None`），引擎拒绝据此开启窗口，相关组结局为 `PENDING`。
- 估计以整数毫秒定点表示；量化误差上界保守取 1ms（真实偏差位于 `[skew-1, skew+1]`）。
- 仅当中位数整数值变化才分配新版本号，版本号从 1 起单调递增；
  `stability_notes` 输出版本间漂移序列与稳定性结论。

## 3. 窗口判定与翻转（业务要求 4）

关键建模决策：**窗口区间在首个有效估计版本出现时锚定，之后跨版本固定。**

- 锚定：用首个有效版本的折算时刻最早的组确定窗口原点 `origin`，再按
  `window_ms` 整数倍向右铺出固定区间 `[origin+k*W, origin+(k+1)*W)`。
- 每个后续估计版本只重新折算各组时刻并对照同一组固定区间判定归属。
  这样偏差平移会改变边界组与固定边界的相对位置，从而产生可记录的翻转；
  若每个版本都重新自适应开窗，加性偏差只会整体平移时间轴，窗口成员永远不变，
  无法表达“偏差估计变化翻转判定”这一业务事实。
- 翻转类型：`OUT_TO_IN`、`IN_TO_OUT`、`WINDOW_CHANGE`，账本记录翻转前后的
  估计版本号与折算时刻。
- 所有判定内部统一按 `(group_seq, frag_offset)` 排序后进行，与片到达顺序无关；
  测试以随机洗牌输入验证窗口开闭序列、翻转集合、丢弃集合、摘要完全一致。

## 4. 槽位预算与在途偏移（业务要求 5）

- 在途偏移：`adjusted_ms - window_base > max_inflight_ms` 即丢弃，
  结局 `OFFSET_DROPPED`，记录当时估计版本。
- 槽位预算：同窗口在途未完成组数达到 `slot_count` 时，按稳定规则
  “折算时刻最早、组序号最小”选择牺牲组，结局 `SLOT_DROPPED`。
- 选择规则只依赖折算时刻与组序号，因此丢弃集合与到达顺序无关。

## 5. 重组与摘要（业务要求 6）

- 重复片按 `frag_offset` 去重（保留最早到达者），不改变已到片集合。
- 片到齐且区间连续时按偏移升序拼装，计算 `sha256` 摘要，与发送端登记值比对；
  不一致以 `E_DIGEST` 标记组失败并入账。
- 已成功组不受后续重复片影响；缺片或区间不连续记 `INCOMPLETE`。

## 6. 账本、快照与恢复（业务要求 7）

- sqlite 单文件账本，`synchronous=FULL`，每条通道的全部记录在一个事务内提交；
  强制终止只可能丢失最后一个未提交事务，已提交记录才可用于恢复。
- 快照持久化通道声明版本（`config_version`）、脚本版本（`trace_version`）、
  各通道估计版本、窗口轨迹、槽位/丢弃、组结局，并携带规范化 JSON 的
  `content_digest`。
- 重开时先比对版本与摘要：任一不符抛 `E_SNAPSHOT`，调用 `replace_all()`
  整体替换通道、参数与窗口状态，不做增量合并。
- 恢复时窗口内未落定组（`PENDING`）统一标记 `UNKNOWN`，要求重跑；
  组件不承诺生成强制终止时刻的退出报告。

## 7. 重放校验与异常注入（业务要求 8）

- 恢复后用同一 `trace_version` 重新裁决，逐字段比较估计序列、窗口事件、
  翻转、结局、逐片记录；首个不一致定位到通道标识、组序号与字段名并抛 `E_REPLAY`。
- 三类注入：声明损坏→`E_CHANNEL`；样本下限抬高→`E_ESTIMATE`；
  快照摘要篡改→`E_SNAPSHOT`，全部写入 `logs/events.jsonl` 结构化日志。

## 8. 真实链路与确定性的关系

- `transport.UdpReceiver` 在真实 `127.0.0.1` UDP 套接字上接收，片头为
  46 字节定长大端头（magic/版本/通道/六个 uint32/CRC32）+ 负载，
  解码校验长度自洽、偏移上限、总片数正数、CRC。
- 真实单调时钟受 OS 调度抖动影响，单次真实链路用于验证收发与片头自洽；
  逐位可复现的偏差/窗口/翻转验证通过 `ReplayClock` 与脚本声明的
  `arrive_ms` 完成，这是“多次回放逐位一致”要求的可执行实现。
