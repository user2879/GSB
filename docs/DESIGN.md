# 设计说明

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `v1.py` / `v2.py` | 两版本解析、字段/类型校验、格式指纹 |
| `unify.py` | 图像发现与校验、版本配对、统一定点表示、帧缓存键 |
| `conversion.py` | 双向转换、sidecar、序列化回读、偏差直方图 |
| `matching.py` | 类别内 IoU 匹配、轨迹串联、池逐出/重入、轨迹缓存键 |
| `snapshot.py` | 不可变阶段快照、manifest、原子发布、有效快照扫描 |
| `engine.py` | 并发流水线、帧/轨迹复用、失败隔离、报告生成 |
| `injection.py` | 复制工作区并施加真实输入故障 |
| `generator.py` | 固定种子 PNG、真值、v1/v2、配置与编辑序列 |
| `validation.py` | 完整验收编排和 Markdown 摘要 |

## 2. 统一中间表示

坐标使用 `10^fixed_decimal_places` 缩放的整数，避免浮点排序与 IoU 在不同线程/序列化路径上的细微差异。得分使用百万分单位整数，报告输出千分比。`RawCandidate` 保留原始精度标签、源版本、源序和额外元数据；`CanonicalCandidate` 是匹配和缓存使用的规范结构。

统一过程同时解析 v1 和 v2：

1. 检查必要字段、有限数、分数范围、类别码表、框单调性和图像边界。
2. 按得分千分比、整数框、类别排序候选。
3. 配对相同序列/帧的候选，比较类别、整数框和千分比得分。
4. 任一不满足时记录失败并从轨迹输入中移除整帧。
5. 根据 `exchange_config.json` 选择 v1 或 v2 作为当前活动表示；另一版本继续用于互操作校验与转换报告。

v2 可以保留亚像素坐标与亚千分比得分，因此统一配对使用“还原到整数像素/千分比后相等”的语义；精度损失由转换 sidecar 和直方图显式量化。

## 3. 匹配与候选池

匹配按 `(series_name, class_code)` 独立执行。对每一帧：

1. 关闭空档超过 `max_gap_frames` 的活跃/被逐出轨迹。
2. 对活跃轨迹与当前候选建立 `IoU >= threshold` 的候选对。
3. 按 `(-IoU, track_id, candidate_index)` 贪心一对一分配。
4. 未匹配候选优先尝试同类别、仍在空档内的被逐出轨迹；成功则标记重新入池。
5. 否则创建确定性轨迹 ID。
6. 活跃轨迹数超过容量时，按保留顺序 `(score desc, coordinate lex asc)` 的尾部逐出。

轨迹每帧记录整数框、千分比得分、中心 `(qx, qy)` 和逐帧速度。轨迹依赖键覆盖首末帧之间全部帧缓存键，以捕捉空档帧中的新候选。

增量运行时：

- 帧缓存键未变：直接采用缓存候选。
- 轨迹所有依赖帧键未变且匹配配置指纹相同：该轨迹整体复用，候选从重算池中移除。
- 仅剩余候选进入 IoU 匹配，未失效轨迹不重算。
- 最终对固定轨迹构成重放池生命周期，只恢复逐出次数和重入标记，不重算 IoU/轨迹构成。

因此最终轨迹 ID、组成、框、得分和池状态与全量运行一致。

## 4. 缓存键

帧键：

```text
SHA256(
  frame_content_fingerprint,
  detection_parameter_fingerprint,
  format_version_fingerprint,
  sidecar_metadata_fingerprint,
  fixed_decimal_places,
  canonical_candidate_payload
)
```

轨迹键：

```text
SHA256(
  algorithm_version,
  match_config_fingerprint,
  series_name,
  class_code,
  ordered_track_frames,
  dependency_frame_keys[first..last]
)
```

并发数和快照提交间隔不进入结果缓存指纹；它们只影响调度与提交频率。该设计保证相同输入下 1 线程与 N 线程结果一致。

## 5. 快照协议

每个阶段提交为新的不可变版本目录。提交步骤：

1. 在 `versions/.tmp-*` 中写入本阶段及其依赖阶段产物。
2. 生成 manifest，包含产物 SHA-256 和阶段版本。
3. fsync 所有文件与目录。
4. 原子重命名临时目录为 `versions/<12位版本号>`。
5. 原子替换 `CURRENT.json` 指针。

恢复不信任可能存在但损坏的 `CURRENT.json`，而是扫描所有版本目录，验证 manifest、路径和每个阶段产物哈希后，选择最高有效全局版本。`.tmp-*` 目录永不参与恢复。

阶段提交示例：

```text
detection      -> 仅检测阶段快照
matching       -> detection + matching
serialization  -> detection + matching + serialization
```

快照提交间隔以序列批大小控制阶段性提交频率。部分检测/匹配快照可用于强杀后继续，但只有完整 manifest 校验通过的目录可被采用。

## 6. 失败链

帧级异常不会终止其他序列。处理顺序：

1. 解析阶段：v1 截断/错位、v2 字段错误。
2. 检测阶段：PNG 校验、逐帧非有限权重。
3. 统一阶段：坐标、得分、类别、版本配对。
4. 匹配阶段：注入的匹配异常或匹配不可用。
5. 序列化阶段：注入/真实序列化异常。

失败记录包含序列、帧号、阶段、业务码、异常类型、消息、详情和注入项编号。所有进入失败集合的帧在最终轨迹中被剪除；轨迹若仍跨空档则由匹配配置决定是否合法。

## 7. 确定性与排序

- 文件读取与输出均使用 UTF-8。
- 候选排序：得分降序、整数坐标字典序、类别、源序。
- 序列处理：按序列名排序；线程池只并行独立序列。
- 轨迹排序：序列名、起始帧、类别码、轨迹 ID。
- 失败排序：序列名、帧号、阶段、业务码、注入编号、消息。
- 最终输出与线程完成顺序无关。

## 8. 已知语义边界

- “从空白全量重建”与“增量运行”的 `reused/recomputed` 运行操作标签必然不同；验收比较所有最终结果字段，并对失效/复用 ledger 比较最终 cache-key 依赖投影。该投影可逐条审计每个帧和轨迹的最终依赖是否与全量结果一致。
- `E_xxx` 是报告/stderr 业务码，不改变成功完成运行的进程退出码；仅配置/IO、未预期异常和模拟强杀使用非零退出码。
- 当前工具不使用模型权重；候选文件被视作检测交换产物，检测阶段负责图像配对、参数指纹和候选有效性。合成样本由真值框加确定性抖动与低分噪声轨迹生成。
