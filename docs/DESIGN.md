# 长序列注意力热块稀疏化算子诊断 — 技术设计

## 1. 业务问题与反馈环

长序列下不会让每个查询块对全部键块打分，而是仅保留少量“热”键块。本应用把该过程建模为
确定性反馈环：

```
张量解析 → 块级定点打分 → 分数下界筛选 → 选择位图 → 热块表统计
                ↑                                      │
                └────────── 下一轮依据上轮统计重选 ──────┘
```

- 选择位图与热块表均被持久化缓存；
- 任一张量块或配置变更，只沿依赖图向下精确失效；
- 定点累加、舍入、排序与逐出全部确定化，保证同输入逐元素一致。

## 3. 二进制张量包格式

全部整数为小端：

```
magic   = b"HSPK"
version = uint32(1)
n       = uint32
重复 n 次:
  name_len uint16, name utf-8
  ndim     uint16
  shape    ndim * int64
  count    int64
  data     count * float32 小端
crc32   uint32，覆盖 CRC 之前全部字节
```

形状乘积必须等于元素数，文件必须以 CRC 结尾。少字节触发 `E_PACK_TRUNCATED`；
CRC 不匹配或形状不一致触发 `E_TENSOR_LAYOUT`。

## 4. 定点打法语义

1. 量化档位 `q4/q8/q12/q16` 对应小数位宽 4/8/12/16，量化值为有符号 Qf 整数并按档位数域饱和。
2. 乘积累加使用声明的 `acc_bits` 有符号整数缓冲；`saturate` 模式越界即钳制，
   `wrap` 模式按二的补码回绕；两种模式都记录 `(qb,kb,row,col,dim,raw,clamped)`。
3. 累加顺序固定为查询块内行号升序 → 键块内列号升序 → 维度升序。
4. 缩放因子 `scale = 2^(-2*frac_bits) / temperature`；每个整数累加结果先乘缩放因子，
   再按 `truncate / nearest_even / nearest_up / floor` 之一用 `Decimal` 确定性舍入。
5. 块对指纹覆盖累加矩阵、缩放因子与舍入模式，长度 16（SHA-256 前 16 位十六进制）。

纯 Python 标量累加 + Decimal 舍入避免浮点归约顺序差异，因此跨线程、跨运行、跨平台一致。

## 5. 选择反馈迭代

- 第一轮对全部 `(qb,kb)` 打分；后续轮只对当前位图引用的块对打分，未变化块对直接复用。
- 每个查询块以本轮最大块对得分乘 `score_floor_ratio` 为下界，容差取自配置。
- 入选排序：得分降序，同分按键块序号升序；最多保留 `candidates` 个。
- 位图与上一轮相同即收敛；达到 `max_rounds` 仍未收敛输出 `E_SELECT_UNCONVERGED`，
  保留最后位图与完整轨迹，不静默返回。

## 6. 缓存键与依赖失效

三类缓存键：

- 块对：查询块指纹 + 键块指纹 + 量化档位 + 累加位宽 + 饱和策略；
- 位图行：查询块指纹 + 预筛指纹 + 档位 + 迭代轮次；
- 热块表：引用的位图行键集合 + 容量 + 保留数 + 档位 + 轮次。

依赖图边为 `块对 → 位图行 → 热块条目`。查询块/键块替换时，先按当前指纹计算受影响块对键，
只失效这些键的可达后代；预筛参数（非块长）变更只失效位图与热表，块对整数算子继续复用；
量化档位变更使全部块对算子失效；热块容量变更只失效热表。所有复用、重算、失效动作进入
`cache_audit`，可审计。

## 7. 热块表确定性更新

- 排序键：累计选中次数降序 → 累计得分降序 → 键块序号升序。
- 容量满时逐出最少选中次数者，同次按键块序号升序；当前轮新入选块不会被逐出。
- 逐出即删除计数，再次入选从 0 累计，禁止继承。
- `hot_keep` 大于容量时以容量为准，并记录 `keep_exceeds_capacity` 压制。
- 热表可由每轮位图与块对得分通过 `HotTable.rebuild` 完整重建。

## 8. 预算与并行调度

- 线程池最大并发严格取 `threads`；预算记账只在编排线程按稳定键 `(qb,kb)` 执行，
  工作线程完成顺序不影响扣减序列。
- 每个查询块每批有 `qblock_quota`，超出记 `E_QBLOCK_BUDGET_EXHAUSTED` 并把任务放入待办。
- 全局每批 `batch_budget` 耗尽记 `E_SCORE_BUDGET_EXHAUSTED`，待办下一批优先并按稳定序重排。
- 缓存命中是复用持久化算子，不重复消耗打分点数；因此预算受限路径的扣减序列是同计划
  全量序列的稳定有序子序列，最终字段仍与全量运行一致。
- 调度器为引擎持久成员，跨 `run_to_completion` 调用累计扣减序列，支持暂停/恢复。

## 9. 快照、恢复与信号

- 四个阶段 `tensor_parse / block_scoring / selection / hot_summary` 先写 `staging`，
  再通过目录 `os.replace` 整体替换到 `committed`。
- 清单记录全局版本、配置哈希、张量指纹、完成轮次、各阶段版本与提交间隔。
- 启动恢复时版本号、配置哈希、张量指纹任一不一致输出 `E_SNAPSHOT_STALE` 并全量重建。
- `SIGTERM/SIGINT` 只设置标志位，当前批/轮产物落盘后以退出码 0 停止。

## 10. 故障注入隔离

注入配置独立于常规配置：

- `nonfinite_scale`：仅目标块对产生非有限缩放，记 `E_NONFINITE_SCALE`，其余块对继续；
- `force_overflow`：目标块对强制饱和，记 `E_ACC_OVERFLOW` 与溢出位置；
- `truncate_pack`：生成截断包，解析阶段致命中止；
- `tamper_snapshot`：篡改已提交清单，恢复判定输出 `E_SNAPSHOT_STALE`。

每条失败记录含块对标识、阶段名、业务码、异常类型与注入编号。

## 11. 退出码约定

| 码 | 含义 |
| --- | --- |
| 0 | 收敛、信号安全落盘或可恢复注入下完成 |
| 2 | 张量/配置/命令/截断等致命输入错误 |
| 3 | 达到批次预算上限暂停，待办已持久化，可再次运行恢复 |
| 4 | 张量包截断致命中止 |
