# 设计说明

## 1. 确定性样本

每个档位使用 `SeedSequence([seed, size, region_size])` 初始化 NumPy PCG64。生成顺序固定为：区域底价、逐格噪声、区域边界墙与门、可选区域内部墙、掩体、地形门价、单位、目标池、查询。地图序列化采用固定小端 dtype 和 C 顺序，内容哈希覆盖档位、种子、形状、移动规则和四个层。

同一 seed/tier 的两次生成会写出两棵目录树并逐文件比较。元数据包含地图哈希、区域数、扇区数、单位数、查询数、单位清单哈希与查询清单哈希。

## 2. 求解器与精确性

### 四邻域 A*

进入格子的代价为 `terrain[cell] * mobility.cost_multiplier`，起点不计费、目标计费。缺省启发式是 Manhattan 距离乘该移动类别的最小进入代价，可配置为 `zero` 或 `euclidean_ceiling`。堆键为 `(f, h, g, cell)`，邻居按扁平索引升序处理，因而相同输入得到相同路线。

### 区域流场

流场在源/目标共同的战术区域内做反向 Dijkstra。`dist[target]=0`，从当前格向邻居松弛时加入当前格的进入代价；随后为每个格记录使 `dist[c] == enter(neighbor) + dist[neighbor]` 成立的最小邻居方向，按固定邻居顺序破同价。查询从起点沿方向场下降即可重建路线。small 档全部查询都做了 A* 与流场双解核验，代价偏差为 0。

### 区域门户分块跳点

战术区域同时作为分块。每块只把与邻块相邻且可通行的边界格作为门户，并预计算门户间区域内最短路。查询时构造完整门户图：

- 块内边：预计算的门户到门户精确距离；
- 跨块边：相邻门户间的一格进入代价；
- 起点/终点边：起点到本块门户、本块门户到目标的局部 Dijkstra 距离。

任何全局路径都能在每个区域边界交叉处分解，因此“完整门户图 + 各块精确局部段”与全图最短路等价。局部 Dijkstra 在所有门户结算后提前停止，但仍保存重建所需方向指针。测试覆盖 small/medium 抽样与 1024 档，CJP 与 A* 代价一致。

## 3. 策略选择

预算来自 `config/demo.yaml`，包含单查询时间、单查询内存、总求解内存、线程数上限与预计算时间。估计器使用地图开放度、查询 Manhattan 距离、区域面积、共享目标组大小与固定 ns 成本参数：

- 稠密 A*：`expansions ≈ distance × (2 + 6(1-open_ratio)) + 64`；
- 区域流场：区域预计算成本按共享目标组均摊，并加路径下降成本；
- 分块跳点：按跨越区域数估计查询成本，并单独检查预计算预算。

候选先按“时间 ≤ 单查询预算、内存 ≤ 单查询预算、预计算 ≤ 预计算预算”过滤，再按 `(estimated_ms, estimated_bytes, strategy)` 确定性排序。三种精确策略的误差上界均声明为 0。

规划缓存签名包含查询字段、地图形状/开放度、预算、流场共享组大小、估计器版本。相同输入全部复用；新增同组查询只重算该组；预算变化重算对应档，未受影响档/组不重算。

## 4. 依赖闭包与增量重算

依赖图节点包括：

- `region:<tier>:<id>`、`chunk:<tier>:<id>`：地图版本基础节点；
- `flow:<tier>:<region>:<target>:<mobility>`：依赖区域节点；
- `jump:<tier>:<region>:<mobility>`：依赖分块节点；
- `path:<tier>:<query>`：依赖路线经过的区域、所引用的流场和分块跳点。

地形/通行编辑先找出受影响区域，构造 region/chunk 脏种子，再沿反向边求缓存节点闭包。闭包内流场、跳点、路径缓存全部删除并重算；流场到路径的级联由依赖边保证。处理顺序固定为 flow → jump → path，实际重算集合必须与闭包集合逐项相等，否则抛出 `E_CLOSURE_MISMATCH`。闭包外节点保留原版本戳和内容哈希，并记录复用来源。

## 5. 一致性核对

增量更新后创建全新引擎，在同一编辑后地图上从头重算全部查询。逐查询比较：

1. 路径代价差是否不超过声明容差；
2. 完整路线序列是否相同。

只有两者同时通过才判定一致；不会因代价相等就忽略序列分歧。不一致时记录首个分歧查询、首个分歧格、所在坐标和路径依赖边。

## 6. 并发与资源预算

流场预计算与查询任务分别提交到 `ThreadPoolExecutor`。结果进入以查询 ID 为键的映射，最终严格按查询键排序输出，与线程完成顺序无关。估计并行峰值超过总内存预算时按固定优先级降级：

1. `serial`：工作线程降为 1；
2. `cache_eviction`：清空可复用缓存并记录前后条目/字节；
3. `minimal_memory`：即使最小单查询估计仍超预算，也不丢查询，记录最小内存模式。

降级记录包含触发原因、优先级、降级前后线程数、缓存条目、字节估算。测试与演示均核对降级前后逐查询路线哈希。

## 7. 原子持久化与恢复

提交顺序：

1. 将完整快照原子写入 `snapshots/<id>/snapshot.json`（临时文件 + fsync + `os.replace`）；
2. 原子写 `COMMITTED.json` 指针，内含快照路径、SHA-256 与 commit sequence；
3. 从已提交快照派生 `dependency_graph.json` 与 `content_hashes.json`。

恢复只读取 `COMMITTED.json` 指向的快照并复核 SHA。序号大于最后已提交 sequence 的快照视为未提交崩溃残留，和 `pending/` 文件一起移入 `orphans/`；历史已提交快照保留。所有快照路线按完整路线序列重新计算哈希，并与提交值逐查询比较。

强制终止演示由子进程写入一个未来快照与 pending 事务后直接 `os._exit(91)`，父进程重启恢复，验证提交路线 12/12 一致。

## 8. 业务错误码

| 错误码 | 触发点 |
|---|---|
| `E_MAP_SHAPE` | 层形状/尺寸、地图边界、无法选编辑格 |
| `E_TERRAIN_RANGE` | 地形不在 [1,9] 或空编辑 |
| `E_DEPENDENCY_STALE` | 缓存依赖版本不匹配、方向场/门户不一致 |
| `E_CLOSURE_MISMATCH` | 实际重算集合 ≠ 闭包、增量与全量分歧、缺查询 |
| `E_BUDGET_DENIED` | 非正预算/线程数、无可用策略、缺决策 |
| `E_UNIT_INVALID` | 单位位置、移动类别、查询端点或不可达路线非法 |
| `E_SNAPSHOT_VERSION` | 配置读取、提交指针、快照 schema/hash/内容损坏 |

底层 `OSError`、YAML 解析错误等通过 `raise TacticalError(...) from exc` 保留异常链。

## 9. 确定性边界

规范报告只包含路线、代价、展开数、逻辑工作量、估算字节、闭包集合、版本戳和 SHA，不包含实际墙钟时间或进程 RSS；这两者天然受机器调度影响。实际运行耗时另在验证记录中说明。因此“两次同输入逐字节一致”适用于所有规范产物，而不是物理时钟诊断。
