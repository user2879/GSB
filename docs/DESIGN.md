# 本地语音诊断组件设计

本文说明 `voice_diag` 的输入、算法、确定性约束、缓存依赖、调度语义、快照恢复和复核方式。实现不访问网络，不读取真实录音，也不依赖 Docker；全部验证样本由固定整数种子生成。

## 1. 目标与边界

组件回答四个问题：

1. 双门限端点检测和重叠窗能否在交叠说话人场景下稳定复现；
2. 窗跨区间、跨片段时，帧级归属和命令结论是否仍可逐字段复核；
3. 替换单区间音频、修正字级偏移或切换量化档位时，失效范围是否精确；
4. 进程在任意已提交阶段被强杀后，能否从持久化账本恢复出与全量运行一致的结论。

组件验证的是诊断流水线的确定性、依赖追踪和恢复语义，不将合成谐波信号作为真实语音识别准确率基准。

## 2. 模块划分

| 模块 | 职责 |
| --- | --- |
| `config.py` | 配置枚举、参数关系、有限浮点数与量化档位校验 |

| `audio.py` | RIFF/WAVE/PCM16 严格校验、时间线混合、片段窗口切片 |
| `receipts.py` | a1 定宽文本、a2 JSON、统一内部表示和旁路元数据往返 |
| `endpoint.py` | 帧能量/谱平坦度、双门限迟滞、最短段后处理、重叠分析窗 |
| `features.py` | 梅尔能量、过零率、谱质心、定点整数、固定投影和命令后验 |
| `adjudicate.py` | 帧级多窗累计、交叠归属、并列裁决、命令段合并和区间汇总 |

| `viewer.py` | 只读 Tkinter 人工复核视图 |

## 3. 输入契约

### 3.1 配置

`config.json` 固定声明：

- 采样格式：16000 Hz、单声道、16 bit；
- 端点参数：帧长、帧移、高/低能量门限、最短语音、最短静音；
- 分析参数：窗长、窗移、帧长、帧移、梅尔带数、量化档位和定点小数位宽；
- 裁决参数：帧端点阈值、最短命令段、量化半步和重叠帧下限；
- 调度参数：最大并发、单批预算、单区间配额和单窗点数；
- 回执参数：a1 字段宽度、允许的命名量化方案和默认方案。

`quant_scale` 必须属于 `allowed_quant_scales`，`frac_bits` 必须属于 `allowed_frac_bits`。定点分母为：

```text
fixed_denominator = quant_scale * 2^frac_bits
```

### 3.2 清单与音频

每个区间只有一个音频片段，片段本地 PCM 与区间全局采样范围一一对应。区间包含：

- 唯一的 `interval_id`、声明集合内的 `speaker_id` 和全局起止采样；
- 受控字表生成的文本、逐字起止相对偏移和命令真值；
- 片段到达顺序、采集时刻和到达时刻。

`command_stream` 必须引用已声明区间、已声明命令和存在的字项。字级偏移必须位于 `[0, interval_length]`，且起点、终点分别单调不减。

WAV 解析检查 RIFF 总长、chunk 边界和 padding、`fmt` 唯一性、PCM 格式、采样率、声道、位深、block align、byte rate、`data` 唯一性，以及 `data_size / block_align` 是否等于区间采样数。格式错误产生 `E_AUDIO_FORMAT`，记录到报告并跳过该片段；结构或引用错误产生 `E_SCHEMA`。

清单和双回执全部解析通过之前不会创建任何快照目录，因此 `E_SCHEMA` 不会留下部分阶段产物。

## 4. 端点检测

对 16 kHz PCM 按帧长 `L`、帧移 `H` 计算：

- RMS 能量；
- 谱平坦度；
- 组合分数 `score = energy * (1 - 0.55 * flatness)`。

迟滞状态机在高门限 `high_energy` 起始，在低门限 `low_energy` 维持。连续静音达到 `min_silence_frames` 后结束候选段；长度不足 `min_speech_frames` 的段删除；间隔不大于最短静音的相邻候选段确定性地合并。

窗口从时间线起点按窗移推进。每个 `WindowGeometry` 保存：

- `window_id`、窗口序号、全局采样范围；
- 中心落在窗口内的全局帧序号。

窗口所属区间和片段由采样重叠计算，不由说话人身份推断。一个窗若覆盖交叠区，必须同时保存多个区间的引用、重叠帧数和来源可信度。

## 5. 定点特征与命令后验

对每个有效帧按升序计算：

1. `mel_bands` 个梅尔对数能量；
2. 过零率；
3. 归一化谱质心。

每个维度先乘以 `fixed_denominator`，再用 `round_half_away_from_zero` 转为整数。帧内特征维按升序遍历；特征和按帧序号升序、维度升序累加。均值仍用同一舍入规则。

命令投影模型由配置哈希、种子、量化档位、梅尔带数、命令码和命令短语派生。投影的排列与符号来自该指纹的 SHA-256 派生种子，不使用运行时全局随机状态。每个命令使用固定短语生成离线探针模板；距离按命令码升序计算，softmax 权重也按命令码升序归约。

后验用百万分比整数表示，并将舍入余量加到最优命令码，保证每个窗的命令后验和严格为 `1_000_000`。切换 `frac_bits` 或 `quant_scale` 会改变定点中间值、投影输入、后验和下游帧结论，而不只是改变显示字段。

## 6. 帧级归属与命令裁决

每个窗对每个覆盖帧生成一条候选贡献，来源权重严格为：

```text
weight = 后验余量 × 来源可信度 × 重叠帧数
```

来源可信度由说话人声明可信度、字项覆盖率和区间覆盖比例合成。同一帧的多窗贡献先按区间汇总，再计算归属百万分比。

归属规则：

1. 权重最高者获胜；
2. 若余量等于零或落在 `tie_half_step_ppm` 内，按区间起点升序、再按说话人标识字典序、最后按区间标识决断；
3. 发生并列的帧标记为边界帧，并记录 `interval_tie_start_then_speaker`。

获胜区间的窗口后验继续按权重汇总为帧级命令后验。若其他交叠区间的最优命令不同，该帧标记 `contested`，并保存次优区间、次优命令及仲裁原因，不做静默丢弃。命令后验并列时按命令码升序处理。

帧只有在候选语音掩码为真、且帧语音后验达到阈值时才为活动帧。活动帧按连续区间、获胜区间和命令码分组，达到最短命令段后进入 `accepted`，否则进入 `suppressed` 并保留原因。

## 7. 双版本回执

### 7.1 a1

a1 每个区间占一行，字段依次为区间序号、说话人序号、千分比整数置信度和整数命令码。默认布局：

```text
IIIIIIIIIIII|SSSSSSSS|CCCCCC|KKKKK
```

解析要求：

- 每行宽度严格等于字段宽度加分隔符；
- 标识只允许 ASCII 字母、数字、`_`、`.`、`:`、`-`；
- 数字只允许 ASCII `0-9`；
- 非法字符、字段不足或字段溢出抛出 `E_FIELD_TRUNCATED`；
- 重复区间、越界千分比或未知命令码抛出 `E_SCHEMA`。

### 7.2 a2

a2 是 JSON 对象或数组。每条记录包含浮点 `endpoint_confidence`、命名 `command` 和命名 `quant_scheme`。置信度必须是有限值且位于 `[0, 1]`，量化方案必须在配置枚举内。

### 7.3 统一表示与旁路

两种版本都归一为 `ReceiptRecord`，保留：

- 来源版本和物理存储字段；
- 缺失字段标记；
- 从旁路恢复的字段和恢复来源。

a2 降级为 a1 时，sidecar 保存原浮点值、被覆盖字段、截断残差、精度标签、命令名、量化方案和实际渲染值。a1 升回 a2 时，只有 sidecar 渲染值与当前 a1 文本完全一致才恢复被覆盖字段；不一致会产生警告并保留 a1 精度，避免伪造恢复。

## 8. 缓存依赖图

| 阶段 | 缓存键依赖 |
| --- | --- |
| `parse` | 全局版本、配置哈希、清单结构哈希、有效音频内容哈希、跳过片段、双回执归一值 |
| `endpoint` | 全局版本、配置哈希、端点参数、窗几何、混合时间线哈希 |
| `features` | 全局版本、配置哈希、窗口几何、引用片段内容哈希、字项偏移指纹、声学参数 |
| `posterior` | 上游特征键、投影指纹、命令码集合、量化方案 |
| `attribution` | 上游后验键、窗口几何、区间重叠、候选帧掩码、裁决参数、量化方案 |
| `interval` | 区间标识、引用它的窗后验键、回执参数 |
| `adjudication` | 全部窗归属键、裁决参数、回执参数、命令真值和量化方案 |

账本为每个缓存条目保存 `cache_id`、阶段、键、依赖、引用集合、稳定排序键和负载。命中、失效和首次 miss 都进入审计。失效原因由依赖差异生成，例如：

- `audio_content_changed:I002`；
- `transcript_offsets_changed:I002`；
- `parameters_changed`；
- `receipt_parameters_changed`；
- `conclusion_upstream_window_changed`。

单区间音频替换或字级偏移修正只改变引用该区间的窗口及其下游区间、裁决缓存；其他窗口直接复用。命令真值发生变化时，声学窗口仍可复用，但裁决缓存键包含真值映射，因此审计报告不会保留旧的真值比较。

## 9. 调度、预算与配额

每个任务携带由阶段、片段到达序号和窗口序号派生的稳定键。批量执行流程：

1. 对待办任务优先、稳定键次之排序；
2. 先判断单批剩余预算，不能容纳的任务直接进入待办队列；
3. 仅对已纳入预算的任务检查每区间配额；
4. 任一已纳入任务超配额时，整批在提交执行前中止并产生 `E_QUOTA_EXCEEDED`；
5. 预算不足产生 `E_POINT_BUDGET_PENDING`，下一批优先消费待办。

线程池最大工作数不超过配置值。任务结果按 `cache_id` 排序后写入账本，完成顺序只进入审计，不参与数值归约，因此任意并发度和完成顺序都与串行执行一致。

## 10. 快照与强杀恢复

阶段划分为：解析校验、端点、窗特征、后验、归属、裁决。每次提交执行：

1. 在 `snapshots/.tmp-*` 写入完整 `state.json`、报告和文本；
2. 对文件执行 `fsync`；
3. 将临时目录整体重命名为不可变快照目录；
4. 原子替换根目录 `CURRENT.json` 指针。

快照中同时保存待办队列、片段游标、到达游标、累计预算、业务码计数、阶段状态和缓存账本。强杀可能留下未提交临时目录或孤立旧快照，但 `CURRENT.json` 始终指向完整快照。重启时清理临时目录，从指针加载账本，重新探测各阶段键；已提交阶段直接复用，缺失阶段继续计算。

最终摘要 `unique_replay_digest` 只由帧摘要、命令结论、区间证据和双版本回执文本派生，不包括快照修订号、绝对路径或线程完成顺序，因此全量运行、增量运行和恢复运行可以直接比较。

## 11. 报告与人工复核

`diagnostic-report.json` 包含：

- 双版本输入/输出回执计数、归一摘要和往返检查；
- 帧数、活动帧数、交叠帧数、边界帧清单和争议帧数；
- 多来源窗数量和区间真值匹配数；
- 每条复用/失效审计及业务码计数；
- 待办数量、片段游标、最后批次和唯一复核摘要。

文本镜像 `diagnostic-report.md` 提供快速摘要。生成的回执、sidecar、`final.json` 和 `CURRENT.json` 位于输出目录根部或 `receipts/` 下。

Tkinter 视图读取这些已提交产物，提供区间证据、交叠/边界、复用/失效、回执文本和原始报告五个只读页：

```bash
voice-diag view --out verification/run-full
```

无图形显示环境不会影响 CLI、测试或恢复；视图失败只返回 `E_VIEWER`。

## 12. 业务码与不变量

| 代码 | 触发条件 | 产物语义 |
| --- | --- | --- |
| `E_SCHEMA` | 配置、清单、引用、回执或 I/O 结构不一致 | 不创建部分阶段快照 |
| `E_AUDIO_FORMAT` | 单个 WAV 容器或格式不合规 | 跳过片段，其他片段继续 |
| `E_FIELD_TRUNCATED` | a1 宽度、ASCII 或字段非法 | 不静默截断 |
| `E_QUOTA_EXCEEDED` | 已纳入本批任务的区间累计点数超配额 | 整批不提交窗产物 |
| `E_POINT_BUDGET_PENDING` | 本批预算不足 | 任务留在持久化待办队列 |

核心不变量：

1. 双回执归一字段一致，a1 往返残差可解释；
2. 每个窗命令后验和为一；特征与后验归约顺序固定；
3. 交叠帧保留全部区间来源，并列归属有稳定裁决依据；
4. 缓存失效集由真实依赖变化导出，未受影响窗复用；
5. 任意并发、完成顺序和批边界下最终摘要一致；
6. 强杀后从最后完整快照恢复的最终摘要与全量运行一致；
7. 业务错误不会伪装成成功或留下半写快照。

## 13. 验证方式

```bash
source .venv/bin/activate
python -m pytest -q
python scripts/verify_acceptance.py --out-json verification/acceptance.json
```

自动化用例覆盖严格 WAV 校验、结构错误、双回执归一与旁路恢复、调度确定性、交叠并列裁决、最短命令段、增量音频替换、字级偏移修正、量化档位切换、预算/配额、滚动到达、强杀恢复和只读复核视图。机器可读结果保存在 `verification/acceptance.json`。
