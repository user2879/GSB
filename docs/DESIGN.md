# 边缘缓存分片下发平台 — 首版技术说明

## 1. 范围与运行形态

平台只使用本机回环 `127.0.0.1:20000-20099`，不依赖容器或外部服务。每个缓存节点是
独立的 OS 子进程（`python -m edge_cache.node`），中心侧通过 JSON 行 TCP 协议与节点
通信；配置、确定性样本、账本与快照全部落在本地工作区。

代码分层（均在 `src/edge_cache/`）：

- `config.py`：节点/配额/分片/命令四类文档的整批加载与校验
- `compute.py`：固定种子 NumPy 样本、整数定点量化与校验摘要
- `protocol.py` / `node.py` / `node_pool.py`：JSON 行协议、节点进程与进程池
- `leases.py`：租约生命周期、真实到期回收、容量水位
- `receipts.py`：c1/c2/c3 三格式统一内部表示与无损往返
- `arbitration.py`：权威回执裁决与上游依赖归一
- `fingerprints.py` / `invalidation.py`：内容指纹缓存键与精确失效
- `ledger.py`：可复核账本与内容寻址产物
- `scheduler.py`：确定性 admission 规划 + 有界并发执行
- `snapshot.py`：临时目录暂存、整体替换提交与崩溃恢复诊断
- `runner.py` / `cli.py`：命令流编排与命令行入口

## 2. 配置整批校验

`load_config_dir` 一次性读取 `nodes.json`、`quotas.json`、`shards.json`、
`commands.json`，任何违规都聚合为 `E_CONFIG_INVALID` 失败清单并抛出 `ConfigError`，
不会产生部分生效的配置。覆盖点：

- 节点 id 与回环端口唯一，端口限定在 20000-20099
- 全局并发、每节点租约上限、容量槽位、资源单位均为正整数，且租约上限不超过全局并发
- 配额版本 `seq` 严格递增、显式 `parent` 引用并做无环链校验
- 分片 id/序号唯一，上游引用必须存在，依赖图做 DAG 着色检测
- 定点位宽枚举 `(0,2,4,6)`、量化档位枚举 `(1,2,5,10)`
- 水位满足 `0 < soft <= hard <= 1000`（permille）

## 3. 租约代数与 JSON 行协议

每份租约由节点维护单调代数标签：`acquire` 建立标签 0；`renew`/`release` 必须携带当前
标签，匹配则标签 +1 并追加代数事件，不匹配返回 `E_LEASE_TAG_MISMATCH` 且标签不变。
所有 acquire/renew/release/expiry-release 事件逐条写入 `algebra.jsonl`。

客户端对每个请求建立短连接，避免并发线程共享 TCP 流造成 JSON 粘包。

## 4. 真实回收与容量水位

中心侧 `LeaseManager` 以单调毫秒记录签发/到期时间。回收只发生在
`reclaim_expired`：它通过回调对节点发起带标签的 release，真正释放节点租约、整数容量
槽位和全局并发令牌，并记录 `E_LEASE_EXPIRED`，不使用 sleep 或线程超时冒充释放。
admission 同时校验全局并发、每节点租约上限、容量槽位与软/硬水位；跨软水位只预警，
跨硬水位拒绝并写明拒因。

## 5. 三格式回执与无损往返

内部统一为 `Receipt`：

- c1：8+8+8 定宽字段（分片序号、permille 校验率、整数配额码）
- c2：JSON，浮点校验率 + 命名配额版本
- c3：转义键值行，额外保留 digest 与重复投递覆盖引用

c3 -> c1 时无法承载的残差、精度标签、digest、覆盖引用写入按分片序号索引的 sidecar；
c1 -> c3 还原时逐字段取回，并由完整性标签（canonical JSON 的 sha256 前 16 位）校验。
低版本升 c3 的缺失字段使用显式 `∅MISSING∅` 标记，篡改完整性标签会被拒绝。

## 6. 裁决与依赖归一

同分片多节点回执按：c3 覆盖引用 → 配额版本号降序 → 单调时钟毫秒降序 → 节点 id
字典序升序裁决；全部判别式并列时置 `tied=true` 并保留全部候选。结论沿上游 DAG 拓扑
合并，任一上游不可用则下游同步标记 `E_SHARD_UNAVAILABLE`，不会用过期回执充数。

## 7. 指纹、失效与复用

缓存键由上游闭包内容指纹、配额版本指纹、节点定点/量化档位与交换版本号派生，区分
节点摘要、权威回执、分片结论、序列化产物和账本条目。替换单分片只失效其下游闭包；
调整单节点配额/档位只失效该节点摘要及派生结论；格式切换只失效序列化产物。失效、
复用命中与重算分别写入 `reuse.jsonl`。

## 8. 确定性调度与增量=全量

调度分两步：

1. `_plan_admissions` 在纯本地计数器上按分片序号做确定性节点分配与预算/水位校验；
2. 线程池按全局并发上限执行，结果再按规划顺序回收进账本。

因此账本条目顺序、裁决依据与失败清单不依赖线程完成顺序。增量运行与空白全量重建的
业务账本、失败清单、格式计数逐字段一致；增量路径因复用会跳过部分真实节点租约，
其代数推进次数不超过全量重建，这本身就是复用生效的证据。

## 9. 阶段快照与强制终止恢复

每个批次先在 `snapshots/tmp/<id>/` 写 `config/leases/receipts/conclusions/ledger`
五个阶段，再以 `os.replace` 原子提交 manifest 并切换 `CURRENT` 指针。恢复只信任
`committed/` 下带完整 manifest 的快照；崩溃残留的 tmp 目录被忽略并可清理。报告包含
三格式回执计数、各节点代数推进、到期回收次数、业务码计数、缺失阶段与未完成分片；
可处理退出通过 `exits.jsonl` 写带业务码的退出记录。

## 10. 验证

`pytest` 共 46 个用例，覆盖配置拒绝、定点计算、三格式往返/篡改、裁决与依赖传播、
指纹失效、水位与真实回收、真实子进程代数协议、端到端增量=全量、SIGKILL 恢复。
