# 设计与实现说明

## 1. 分层

- `validation.py`：严格 JSON 解析、集合/索引声明校验、文档投影校验。
- `canonical.py`：规范 JSON、有限数值检查、稳定摘要。
- `models.py`：集合、索引、条目、分段记录。
- `storage.py`：SQLite schema、逐段表、摘要/BLOB、账本、查询历史、审计批次。
- `engine.py`：初始构建、增量重建、查询、诊断。
- `verify.py` / `replay.py`：独立结构校验与审计重放。
- `snapshot.py`：整库快照、内容摘要、只读旧快照、整体替换恢复。
- `inject.py`：三类确定性异常注入。
- `cli.py` / `gui.py`：命令行与 Tkinter 诊断界面。

## 2. 确定性编码

所有持久化摘要均使用 UTF-8 规范 JSON：

- 对象键排序；
- 分隔符固定为 `,` 与 `:`；
- 禁止 NaN/Infinity；
- 原始声明拒绝重复 JSON 键。

段内容 BLOB：

```json
{"entries":[["<value-json>","<pk-json>"], ...],"segment_id":"seg-00000001","version":2}
```

`SHA-256(BLOB)` 即段摘要，覆盖条目序列、段版本与段标识。规范 JSON 保证同值输入跨进程、跨目录得到相同摘要。

## 3. SQLite 结构

固定元数据表：

- `meta`：schema 版本等。
- `collections`：集合名、主键路径、当前集合版本。
- `indexes`：路径、容量、空值策略、索引版本、下一个段号。
- `documents`：规范文档 JSON，供隔离过滤与全量扫描。
- `segments`：段标识、表名、版本、条目数、上下边界、摘要、内容 BLOB。
- `stale_ledger` / `stale_ledger_expected`：陈旧键历史及可核验预期副本。
- `query_history`、`isolation_stats`：查询历史摘要与逐段累计过滤数。
- `audit_baseline`、`audit_batches`：重放基线、每批变更与前后状态。

每个段另有独立表：

```sql
CREATE TABLE seg_entries_<stable-sha-prefix>(
  seq INTEGER PRIMARY KEY,
  value_json TEXT NOT NULL,
  pk_json TEXT NOT NULL,
  UNIQUE(value_json, pk_json)
);
```

段表名由 `(集合名, 索引路径, 段标识)` 的摘要前缀确定，不含时间、随机数或数据库 rowid。

## 4. 初始构建与分裂

条目排序键为 `(数值, 主键类型序, 主键值, 主键规范JSON)`。初始构建按容量顺序切块，段标识从 `seg-00000001` 单调分配，段版本为 `1`。

增量超容量时：

1. 合并该段保留条目与本批目标条目；
2. 按容量计算 `ceil(n / capacity)`；
3. 平衡分块；
4. 首块保留原段标识，版本加一；
5. 后续块使用持久化 `next_segment_number` 分配的稳定标识，版本同样为原版本加一。

批次中的变更先整体物化为最终文档集合，再按旧段边界路由。批次内部顺序、`--batch-size` 分块和独立变更遍历顺序不参与标识分配，因此不会改变最终段集合。

## 5. 原子增量应用

应用流程：

1. `BEGIN IMMEDIATE`。
2. 校验集合版本与所有索引版本相等；不对过期状态做增量合并。
3. 在内存副本中按原顺序物化删除、插入、替换与字段更新。
4. 对每个变更文档执行完整索引投影校验。
5. 计算最终文档与全部索引期望条目。
6. 扫描当前物理条目，识别不在最终投影中的陈旧引用。
7. 写入陈旧账本；正常模式下从所属段物理移除。
8. 仅为有移除或新增的段计算新条目集合。
9. 整体替换受影响段：DROP/CREATE 段表、写元数据、递增段版本。
10. 读取替换后的段，显式断言所有未受影响段内容 BLOB、版本与摘要完全一致。
11. 若已回收，断言物理条目集合等于当前文档投影。
12. 更新索引版本与集合版本、同步账本预期、写审计批次。
13. `COMMIT`；任一步异常整体回滚。

`--retain-stale` 跳过第 7 步的物理移除，但账本仍记录，查询仍按当前文档过滤，用于验证停滞窗口。

## 6. 陈旧账本

账本主身份为 `(集合, 索引路径, 主键, 陈旧键值)`，原因字段为：

- `document_delete`：文档已不存在；
- `key_migration`：文档存在，但索引路径值已改写或变为空。

相同身份重复识别不会产生重复行；首次原因、原段与发现版本保留，`last_seen_collection_version` 只单调更新。`stale_ledger_expected` 是最近一次正常应用的完整预期副本，用于检测账本缺失注入。

## 7. 查询与陈旧隔离

查询先比较所选索引版本和集合版本；不一致在产生任何结果前返回 `E_STALE`，包含 `stale_dimension`、`collection_version`、`index_version`。

索引查询按段边界键筛选候选段，再逐条判断：

1. 数值范围/等值条件；
2. 当前文档是否存在；
3. 当前索引路径值是否仍等于条目值。

不满足 2/3 的条目为陈旧引用，被过滤并累计到 `isolation_stats`。剩余结果按 `(值, 主键)` 全局排序，再做偏移/限制分页，因此分页跨段连续。全量扫描从 `documents` 重算投影，使用相同排序与返回结构；测试逐项比较两者。

## 8. 快照

快照目录：

```text
snapshots/snap-000001/
  snapshot.db
  manifest.json
```

`manifest.json` 包含集合版本、索引版本、全部段摘要、账本、查询历史摘要、数据库 SHA-256 和整体内容摘要。创建时通过 SQLite backup API 生成一致副本，再原子改名并写入规范 JSON。

恢复时：

1. 重算 manifest 内容摘要与数据库摘要；
2. 逐项比较集合版本、索引版本、段摘要、账本摘要、查询历史摘要；
3. 输出逐段差异明细；
4. 复制快照数据库到临时文件并 `os.replace`，整体替换当前库，不做合并；
5. 重开数据库并再次与 manifest 比较；
6. 保留只读快照与恢复前回滚副本。

## 9. 校验与重放

结构校验独立于正常写入路径：

- 从段表读取条目并重算 BLOB/摘要；
- 比较边界、条目数、段内顺序与跨段范围；
- 比较实际账本与预期账本。

重放从 `audit_baseline` 创建全新临时会话，按顺序重放每个变更批次，并比较每批前后段状态、未受影响段摘要、最终段摘要和账本身份集合。首个差异通过 `segment_key`、`segment_id` 与 `field` 定位，以 `E_REPLAY` 返回。

## 10. 异常注入映射

- `segment`：只改某段 `segments.digest`，触发 `E_SEGMENT`。
- `bound`：只改某段 `entry_count`，触发 `E_BOUND`。
- `ledger`：只删除一条实际账本行，保留预期副本，触发 `E_LEDGER`。

注入只修改会话输入文件/参数，不修改正常代码路径。

## 11. 已知边界

- 当前每集合一个索引声明。
- 删除/迁移会使段变小，但不做跨段合并；这优先保证未受影响段逐字节不变。
- 支持有限整数/浮点数值，不支持 NaN、Infinity、布尔值冒充数值。
- Tkinter 是运行诊断 GUI 的可选组件；核心与测试不依赖图形环境。
