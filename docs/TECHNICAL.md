# 配置权威仲裁与失效诊断技术说明

## 1. 运行边界

- 运行环境：Python 3.11、numpy；GUI 额外使用官方 Python 自带的 Tk。
- 服务只绑定 `127.0.0.1` 高位端口，不使用容器、外部服务或网络目标。
- 平台以 `subprocess.Popen` 为每个环境启动独立服务进程，通过真实 TCP 套接字逐行交换 JSON。
- 本地样本为 `samples/sample_spec.json`，默认服务端口 `46301`、`46302`、`46303`。运行前须确认端口空闲。

## 2. 声明与 E_SPEC 强校验

根对象包含：

- `format_version`：整数，当前固定为 `1`。
- `session`：缩放指数、整数种子、样本数、组大小、噪声上界、全局并发、每环境并发、握手超时。
- `environments`：环境标识、`127.0.0.1` 字面量、全局唯一端口、十进制权重及严格递增的切片版本历史。
- `views`：视图标识、参与环境集合、每个逻辑键的仲裁口径与非负整数容差。

校验按固定顺序执行，失败立即抛出 `E_SPEC`，`field` 使用稳定 JSON 路径定位首个非法字段。已覆盖：

- 环境标识、视图标识、参与环境列表内部重复；
- 非 `127.0.0.1` 字面量、端口越界、端口全局重复；
- 每环境切片版本不严格递增；
- 参与环境不存在、仲裁口径未知、容差为负或非整数；
- 权重量化后为零、数值非有限、空键集合、样本组参数不整除。

## 3. 子进程服务与逐行回执

每个环境服务启动时绑定声明端口，并在标准输出打印一行：

```json
{"event":"READY","service_id":"cn-prod","host":"127.0.0.1","port":46301}
```

平台请求包含服务标识、切片版本与值、缩放指数、整数种子、样本参数。服务为每个键派生固定 PRNG 种子，用 numpy 生成固定数量的整数样本，按固定组大小分组并做整数定点聚合。每个组做零和中心化，使分组均值精确回到量化切片值；种子仍决定完整样本轨迹与 `sample_digest`，并进入权威摘要输入。

服务回执字段：

- `service_id`
- `slice_version`
- `aggregate_summary`
- `sample_digest`
- `digest`
- `elapsed_ms_monotonic`

错误映射：

- 端口已被占用或服务启动失败：`E_PORT`；
- 服务就绪或套接字握手超时：`E_TIMEOUT`，超时由真实 `socket.settimeout` 触发；
- 回执缺字段、字段类型错误、服务标识或切片版本不匹配：`E_FIELD`。

## 4. 定点量化、截断和饱和

会话缩放因子为：

```text
S = 10^scale_exponent
q(x) = trunc_toward_zero(x * S)
```

键值和环境权重都经过同一整数定点入口。截断方向固定为“向零截断”，因此单次量化误差满足：

```text
0 <= |x*S - q(x)| < 1
```

所有加、乘、乘除结果限制在有符号 64 位整数范围：

```text
[-9223372036854775807, 9223372036854775807]
```

溢出时饱和到边界；加权均值先做饱和乘法，再做向零整除，最后饱和。该规则在每个键结果的 `error_bound` 中以 `truncation_direction` 和 `overflow_rule` 明示。

## 5. 三类确定性仲裁

设环境 `i` 的候选整数摘要为 `V_i`，量化权重为 `W_i`，切片版本为 `s_i`，键容差为 `T`。

### 5.1 最新切片优先

按 `(slice_version 降序, environment_id 升序)` 选一个环境。输出该环境的整数摘要，采纳集合只含胜者。

### 5.2 按权重加权多数

按摘要升序构造容差簇：候选与簇首的定点差不超过 `T` 时进入同一簇。每簇权重和为支持度，按：

```text
支持度降序, 簇加权均值降序, 环境标识元组升序
```

选出胜簇。采纳集合为胜簇全部环境，权威整数为：

```text
trunc_toward_zero(sum(W_i * V_i) / sum(W_i))
```

### 5.3 按数值区间交集中点

每个候选形成闭区间 `[V_i-T, V_i+T]`。在所有候选下端点处扫描重叠集合，按：

```text
重叠权重支持降序, 交集宽度升序, 交集下界升序, 环境标识元组升序
```

选出胜交集，采纳集合为覆盖该交集的环境。权威整数为：

```text
trunc_toward_zero((交集下界 + 交集上界) / 2)
```

三个候选列表和所有 JSON 映射在计算前都排序；权威摘要使用排序后的规范 JSON 与 SHA-256。因而不依赖字典、哈希或上报顺序。测试对三口径候选列表反复洗牌，逐字节比较 `result_json` 与 `result_digest`。

## 6. 误差界与三段贡献

每个键的误差界分解为：

```text
q_k = ceil(最大键值截断误差) + ceil(最大权重截断误差)
d_k = max(三口径结果) - min(三口径结果)
a_k = min(T, q_k + d_k)
B_k = q_k + d_k - a_k
```

- `q_k`：量化截断贡献，权重误差采用保守的整数单位累加；
- `d_k`：仲裁口径差异贡献；
- `-a_k`：容差吸收贡献，输出字段为负值；
- `B_k`：合成单键判定误差界。

三段严格满足 `B_k = q_k + d_k + (-a_k)`。视图级上界采用各键绝对上界的 L1 聚合：

```text
B_view = sum(B_k)
```

视图级三段贡献也分别求和，字段位于视图摘要的 `error_bound`。

## 7. 不可区分、决胜与归因

对当前口径选中的整数摘要，计算它与最近被否候选的定点差 `runner_up_delta`。若：

```text
runner_up_delta <= B_k
```

则标记 `indistinguishable=true`、`primary_cause=ERROR_INDISTINGUISHABLE`，但结论仍由各口径的固定决胜规则确定。所有规则只使用版本、量化权重、整数摘要和环境标识，不使用时间或到达顺序。

每个键的互斥主要成因优先级：

1. 误差不可区分；
2. 三口径结果不一致，即口径冲突；
3. 被否环境数严格超过候选数一半，即被否占比过高；
4. 无异常。

视图级 `cause_shares` 为各主要成因键数除以视图键数，因此占比之和为 1；`cause_percentages` 提供同一数值的百分比形式。

## 8. 双配额并发调度

`BoundedScheduler` 使用真实 `ThreadPoolExecutor`，工作线程名前缀为 `arbiter-dispatch`。并发门由两重条件保护：

- 全局在途数不超过 `global_concurrency`；
- 单环境在途数不超过 `per_environment_concurrency`。

任务只在真正套接字下发期间占用在途配额。配额不足时线程在条件变量上等待，并记录：

- `enqueued_monotonic_ms`
- `worker_started_monotonic_ms`
- `quota_wait_start_monotonic_ms`
- `quota_wait_end_monotonic_ms`
- `socket_started_monotonic_ms`
- `socket_ended_monotonic_ms`
- 派生等待、套接字耗时与工作线程名

超时只来自套接字 `settimeout`，应用不注入睡眠或人为延迟。

## 9. 失效传播与整体替换

切片变更先逐键比较旧、新规范化值：

- 只有值实际变化的键才进入候选受影响集合；
- 若视图参与环境集合包含该环境，且视图声明了该键，则视图受影响；
- 切片版本变化但值未变化，不推导出受影响键。

视图配置变化按参与环境增删、键增删、仲裁口径变化、容差变化分别生成稳定原因。原因先按 `kind/environment/key` 排序，再以规范 JSON 作为最终稳定键。

受影响视图版本号加一；账本先将该视图全部旧结果标为 `is_stale=1`，再写入完整的新版本结果。当前展示和重放只查询 `is_stale=0`。视图删除执行同样的整体陈旧化，并保留历史版本号；重新添加时从历史版本继续递增。

若用户在 JSON 中移除整个视图后重启 `run`，引擎会比较当前声明与账本中的活动视图，将缺失视图整体陈旧化并记录 `VIEW_REMOVED_FROM_SPEC`，避免旧结论因不再被遍历而意外保持“当前”。

账本视图元数据同时保存上一次视图配置与参与环境切片快照。重启后可按同样的环境→键→视图引用关系精确比较：真实值变化只失效相关键；仅切片版本变化不会提升视图版本，而是用同一视图版本刷新来源快照；参与环境或规则变化则按对应原因提升版本。

## 10. SQLite 账本、快照与重放

每个视图仲裁在同一个 `BEGIN IMMEDIATE` 事务中写入：

- 视图版本、配置摘要、配置内容与参与环境切片快照；
- 每键权威摘要；
- 采纳、被否环境集合；
- 定点误差界；
- 归因；
- 切片版本与来源回执摘要；
- 传播事件；
- 新的账本内容摘要。

账本同时保存整数格式版本和内容摘要。内容摘要覆盖视图元数据、全部结果（含陈旧行）、传播事件与整库替换审计记录。重新打开时：

1. 校验表结构、`PRAGMA user_version`、`meta.format_version` 与内容摘要；
2. 任一不一致时关闭连接，将整个旧库移动到 `*.replaced.N`；
3. 创建全新账本，并按稳定序号列出 `field/previous/current` 差异。

强制终止只可能丢失未提交事务。SQLite WAL 回滚后，重新打开只能看到已提交行。`replay` 会从声明和确定性服务重新计算当前视图，按 `view_id/key` 稳定顺序逐字段比较；首个差异抛出 `E_REPLAY`，上下文包含 `key` 和 `field`。

## 11. GUI 与 CLI

CLI 是完整诊断入口：

```bash
python3 -m config_arbiter run --reset
python3 -m config_arbiter replay
python3 -m config_arbiter demo
```

Tk GUI 提供声明加载、服务启动、仲裁执行、重放、切片变更模拟、结果表和完整 JSON 详情：

```bash
python3 -m config_arbiter gui
```

当前验证容器没有 Tk 动态库和图形显示，因此自动化验收使用 CLI；GUI 代码在官方 Windows Python 安装包提供的 Tk 环境中运行。

## 12. 已知取舍

- 权重量化误差以保守整数单位并入量化段，不做量纲归一；这是明确的工程保守策略。
- 区间口径在无全量交集时选择最大权重重叠子集，而不是拒绝产出；这保证任何可用候选都产生唯一权威摘要。
- 服务样本组采用零和中心化，避免固定的切片值因样本偶然漂移而被误判；样本种子仍通过轨迹摘要进入权威摘要。
- 当前工作区没有 Tk 运行库，因此未执行 GUI 截图测试。
