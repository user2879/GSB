# FixedVideo 技术说明

## 1. 目标与不变量

应用在本地 CPU 上模拟一条多阶段视频扩散管线。核心不变量是：

1. 同一提示词、种子和静态配置下，编码向量、初始化和逐阶段产物逐元素一致；
2. 所有随机数都由内容哈希派生的局部 `PCG64` 生成器产生，不读写 NumPy 全局随机状态；
3. 任意命令历史后的增量最终产物，与直接对最终有效状态执行空白全量渲染，在像素、帧指纹、步摘要、块摘要和必需产物内容上一致；
4. 快照提交以完整代次为单位发布，恢复只读取已提交代次；
5. 并发只影响任务完成时刻，不影响稳定排序键、产物顺序和内容指纹。

## 2. 阶段与数据形状

样本默认形状：

- 潜变量：`3 x 8 x 8`，即 192 个定点整数；
- 帧数：6，命令可增减到 8；
- 帧分辨率：`32 x 40 x RGB`；
- 嵌入维度：32；
- 噪声表：`24 x 8 x 3 x 8 x 8` int64；
- 定点位宽：12 bit，即 scale 为 4096；
- 分块行数：8，可切换到 4，每帧分别得到 4 或 8 个块。

### 2.1 提示词编码

`normalize_prompt` 只保留小写 ASCII 字母和数字。编码按受限词表顺序遍历：

```text
digest = SHA256("fixedvideo-token|" + token)
embedding_index = int(digest[0:16], 16) % embedding_dim
sign = -1 if int(digest[16:18], 16) & 1 else +1
value_fp = sign * round(1_000_000 * count / known_token_count)
embedding_fp[embedding_index] += value_fp
```

命中记录包含词表索引、词袋维度索引、词频、带符号定点值以及提示词中的位置。未知词按首次出现顺序记录但不进入嵌入。嵌入同时以精确 `embedding_fp` 和十进制表示保存。

### 2.2 初始化

每帧独立派生随机种子：

```text
rng_seed = hash63("initialization", prompt_fingerprint, seed,
                  latent_config_fingerprint, frame_index)
values = PCG64(rng_seed).standard_normal(192).reshape(3, 8, 8) * 0.32
latent_fp = quantize(round(values * 2^bits), quantization_step)
```

因为按帧派生，帧数从 6 增加到 8 不会扰动第 0–5 帧的初始化值；前序帧缓存可继续命中。

### 2.3 图生视频替换

初始图潜变量由 float32 NPZ 读入，并验证其 `shape` 描述符、数据长度和 dtype。其定点编码使用与文本初始化相同的量化函数。

当 `initial_skip_steps=K` 时，第 `0..K-1` 步不执行噪声更新，而是产生 `image_replace` 产物；第 `K` 步从图像潜变量开始，之后与文生视频路径调用完全相同的 `_compute_step`。这样：

- 修改初始图会真实改变替换步和后续链；
- 修改替换步数会改变进入共享去噪语义的起点；
- 图生视频路径下修改种子仍会改变第 `K` 步之后的结果，因为种子参与噪声表行偏移和条件项随机相位。

### 2.4 定点去噪

所有潜变量以 int64 保存。每步先按固定顺序计算：

```text
noise_index = (step + seed % noise_steps) % noise_steps
noise = noise_table[noise_index, frame]
condition = round_half_away(condition_base * guidance_milli,
                            1000 * (step + 2))
before_quant = previous + noise + condition
after_quant = round_half_away_to_multiple(before_quant, quantization_step)
residual = before_quant - after_quant
```

然后按 `patch_id` 排序应用该步、该帧的局部矩形补丁，并再次量化。补丁矩形作用于全部潜变量通道。元数据记录：

- 舍入残差绝对值之和、最大值和分位数摘要；
- 条件项和噪声项绝对值之和；
- 补丁定点增量绝对值之和；
- 潜变量定点摘要与浮点摘要；
- 补丁 ID、矩形、浮点增量和定点增量。

舍入规则是全阶段统一的 half-away-from-zero，不使用 Python `round` 的银行家舍入。

### 2.5 解码与分块

投影矩阵从配置种子和静态模型指纹派生，形状为 `3 x H x W x 192`，元素为 `-1/0/1`。每行块只读取对应输出行的投影切片：

```text
dot = projection[:, row_start:row_end] @ latent_flat
numerator = dot * output_gain + pixel_bias * scale + 128 * scale
rounded = round_half_away(numerator / scale)
uint8 = clip(rounded, 0, 255)
```

块任务稳定键为 `decode:{frame:06d}:block:{block_index:06d}`。块任务按 `recompute_tile_budget` 分批并发，完成进度可以实时进入 pending 摘要。最终产物中的块列表按块序号排序，`canonical_block_completion_order` 由这些稳定键组成，因此线程完成顺序不会污染内容指纹。切换分块行数会改变分区、块数、稳定键和块摘要。

## 3. 内容缓存与失效

缓存键由以下内容组成：

- 上游产物的内容指纹；
- 当前阶段参数指纹；
- 定点位宽与量化档位；
- 算法/生成器版本字符串。

主要键：

| 阶段 | 关键依赖 |
| --- | --- |
| 编码 | 规范化提示词、词表哈希、嵌入维度 |
| 初始化 | 编码指纹、种子、潜变量几何、量化档位、帧号 |
| 初始图编码 | 原始 float32 内容哈希、量化档位 |
| 每步去噪 | 上一步内容指纹、编码指纹、种子、引导强度、噪声条目、补丁集合、量化 |
| 解码 | 最终潜变量指纹、投影指纹、分辨率、量化、分块行数 |
| 合成 | 有序帧指纹、帧数、分块行数、输出布局 |

因此：

- 引导强度变化：编码和初始化命中，去噪及下游重算；
- 种子变化：编码命中，初始化、去噪及下游重算；
- 步数增加：已有步前缀命中，只计算新增步和最终解码；
- 帧数增加：已有帧全部命中，只新增帧；
- 补丁增加/删除：补丁步之前及未受影响帧命中，补丁步及该帧下游重算；
- 初始图替换：文本编码和文本初始化保持缓存，图像编码、替换步及下游重算；
- 分块行数变化：编码、初始化、去噪全部命中，解码/合成重算；
- 量化档位变化：量化相关初始化及全部下游重算。

每次命令的审计记录包含 `stage`、`status=reuse|recompute`、缓存键、内容指纹、参数指纹、依赖列表、帧号、步号、块号和稳定排序键。

关于“复用与重算清单和全量清单相同”的可执行解释：空白全量运行按定义没有任何缓存命中，因此命中标签不可能与增量运行逐字相同。本项目采用可审计且更强的等价判定：最终必需产物键集合完全相同；每一增量复用产物的内容指纹都与全量重算产物相同；复用键与重算键的并集覆盖同一最终必需集合。验收报告明确记录这一语义。

## 4. 交互延迟预算

主线程提交命令时最多观察预算的前 35%：

```text
deadline = submitted_at + 0.35 * budget
```

快速命令仍可在该窗口内直接返回完成结果；其余情况保留 65% 的时间用于线程池预热、响应组装和调度交还，确保 pending 响应本身不超过配置预算。渲染在单工作线程上串行执行，提交线程若未在窗口内收到完成通知，就返回：

- `E_INTERACT_BUDGET_PENDING`；
- 当前任务的进度，包括阶段、当前步/帧、已完成帧、已完成块/行、受影响帧区间和版本；
- 最近一次已完成的完整预览；
- `result_corresponds_to`、`preview_corresponds_to_version` 和配置指纹，避免把旧预览误认成新参数结果。

命令完成后，CLI 调用 `wait_idle` 等待收敛，再按快照间隔提交。诊断中同时保留即时响应延迟和稳定延迟。

## 5. 并发一致性

`ThreadPoolExecutor(max_workers=worker_count)` 是唯一执行池。去噪按“步内跨帧”并发：同一步的各帧互不依赖，下一步等待上一步全部帧完成后开始。解码按块并发，并受重算瓦片预算限制。

由于：

1. 每个任务读取不可变的上一步产物；
2. 任务键包含阶段、步、帧、块；
3. 结果在提交顺序/块号顺序上重新排序；
4. 内容指纹不包含线程完成时刻；

所以 1 线程与 N 线程得到同一最终帧、同一步摘要和同一内容指纹。

## 6. 快照协议

每次提交创建全新的 `gen-NNNNNN` 临时目录，写入：

- 当前状态所需缓存产物；
- 状态与清单；
- 最终帧、块 PNG、预览条与预览 JSON；
- 投影/条件矩阵；
- 命令、失败、复用/重算报告。

随后使用目录重命名把完整代次移入 `snapshots/`，再原子替换 `CURRENT.json`。提交前后都检查指针代次未变化，因此不会逐文件覆盖，也不会把并发更新的另一代次静默盖掉。

恢复时读取指针和清单，验证：

- 快照 schema 版本；
- 指针与清单代次、全局版本一致；
- 源配置哈希；
- 命令流哈希；
- 请求的显式版本；
- 重新生成的投影指纹；
- 缓存索引计数及各产物内容指纹。

任一失败返回 `E_SNAPSHOT_STALE`，退出码 3。恢复只使用快照目录中已提交的缓存、状态和报告，不读取未提交的进程内状态。

强制终止示例中，快照间隔为 3，运行 8 条命令后强杀，最后完整代次为命令游标 6；`--resume` 从 6 继续，最终 8 帧与无中断增量运行一致。

## 7. 诊断与可复核字段

顶层 `reports/diagnostics.json` 包含：

- 源配置哈希、命令流哈希、快照指针；
- 最终种子、步数、有效配置指纹、trace 指纹；
- 每命令即时响应延迟、稳定延迟、状态、业务码、命中率、复用/重算键、最大并发；
- 失败清单及顺序；
- 最近一次待重算键；
- 快照提交历史；
- 最终帧指纹。

每个帧元数据包含帧内容指纹、PNG SHA-256、原始像素 SHA-256、完整解码参数和逐块摘要。每个步产物包含上游内容指纹、噪声条目指纹、补丁集合、残差和量化参数，因此最终 trace 可以从清单逐级复核到编码与配置。

## 8. 实测结果

环境：Python 3.11.0rc1、NumPy 1.26.4、Pillow 11.0.0。

命令：

```bash
python3 scripts/run_demo.py --samples samples --workdir runs/final-demo --force
```

结果：

- 全部 10 项检查 `true`；
- 预算 8 ms，最大即时响应 6.325 ms，18 条 pending；
- 增量与全量：8/8 帧像素一致、PNG 字节一致、帧指纹一致、178 个必需产物键及内容一致；
- 增量最终命令复用 137 项、重算 41 项；
- 单线程与 4 线程结果一致；
- 恢复游标 6，恢复后像素与全量一致；
- 配置哈希、版本、投影指纹三种 stale 均返回 `E_SNAPSHOT_STALE`；
- pytest：`16 passed`。

这些数字会随采样参数或运行环境有轻微延迟变化，但确定性哈希、像素和恢复等价关系不变。
